# Experiment 11 — AI-native NAS decision

**Decision: REDESIGN, with Impact Rehearsal as the provisional winner and Rebuild Kit as the fallback.** The prototype is a real, statically valid UGREEN-format Markdown Skill. It asks what work might be affected before a user moves, renames or removes a selected file. The result is a sourced impact map and safe next step. This is a credible, bounded NAS workflow, but the tested demo is not yet exceptional: a generic Codex agent produced a comparable map, no person has judged its usefulness, and no real NAS expert has run it.

## 1. What the platform appears to offer

UGREEN describes semantic search, document analysis, knowledge Q&A, file management and local/cloud model choices in its [Model Manager notice](https://ai.ugreen.com/pages/notice-on-model-manager). The installed official catalog documents file discovery and reads, document extraction/reconciliation, evidence collection, photo analysis and other expert-owned operations. The parent Skill delegates to registered experts with actual scoped inputs; it does not directly run their CLI. See [platform reality](../research/11-ai-native-nas/platform-reality.md) for all nine CLI families, approvals, exact actions and limits. It is unknown whether the built-in assistant already offers the full proposed interaction in the same configuration.

A Skill can specify a repeatable trigger, authorized scope, unique expert routing, attributable evidence, failure/approval states and a user-facing result while leaving reasoning to the model. It is not a deterministic permission boundary, a new tool, or a guarantee of better intelligence. It cannot assume custom code, persistent monitoring, interactive graph UI, snapshots or complete dependency discovery.

## 2. Research insights and user opportunity

[Google's 2026 survey](https://research.google/pubs/a-survey-on-agent-skills-externalized-procedural-knowledge-in-language-models/) describes reusable externalized procedural knowledge; [OpenAI's Skills guide](https://developers.openai.com/api/docs/guides/tools-skills) documents modular instruction bundles in its own API environment. [Microsoft SkillOpt](https://www.microsoft.com/en-us/research/blog/skillopt-agent-skills-as-trainable-parameters/) reports bounded skill edits validated on benchmarks with model weights frozen. These are research/vendor findings, not independent UGREEN validation; OpenAI's executable formats do not override the UGREEN Markdown-only rules. There is no evidence that longer instructions are universally superior or unnecessary. Scope, approval and honest evidence limits remain essential regardless of model strength. The [frontier review](../research/11-ai-native-nas/frontier-research.md) records seven insights and their constraints.

Targeted [user research](../research/11-ai-native-nas/user-opportunities.md) found discussions of duplicate-cleanup anxiety, moving media across many projects, and references going offline. Existing tools already solve parts: [Premiere Link Media](https://helpx.adobe.com/premiere/desktop/organize-media/file-organization/locate-and-link-offline-files.html) relinks missing media; [VS Code refactor preview](https://code.visualstudio.com/docs/editing/refactoring) previews supported code changes. A cross-folder, pre-change context preview is a hypothesis about unmet convenience, not a demonstrated unique capability or UGREEN product roadmap.

## 3. Twelve visions and three finalists

The [big-ideas file](../research/11-ai-native-nas/big-ideas.md) examines: Impact Rehearsal, Rebuild Kit, Decision Fork, Negotiation Rehearsal, Format Exit Passport, Skill Recipe Review, Credit Ledger, Resource Swap Ledger, Archive Continuity Drill, Evidence Gap Lantern, Sidecar Context Map and Recovery Storyboard. Negotiation Rehearsal, Skill Recipe Review and Credit Ledger are new specific directions for this project, not claims of global novelty. The Skill Recipe vision is future research: no autonomous self-editing is assumed.

The [selection](../research/11-ai-native-nas/vision-selection.md) compares Impact Rehearsal, Rebuild Kit and Negotiation Rehearsal against UGREEN's four equally weighted judging dimensions, plus separate WOW/risk/effort considerations. It selects Impact as primary because a user can immediately see that a seemingly unused file is referenced by two active projects; it selects Rebuild as fallback because it yielded a complete, editable text handout. These are subjective judgments, not participant ratings.

## 4. Big vision and narrowly scoped MVP

**Longer-term vision (speculative):** Before a change, a NAS could show which work relies on a file across different applications and help the owner plan a reversible migration. No complete graph, app integration or rollback is established in the current toolkit.

**Hackathon MVP:** User specifies an actual file or folder, proposed change and authorized search scope. `file-agent` inventories bounded candidates, `document-agent` examines actual references, and `knowledge-agent` may collect supporting or contrary evidence. Parent synthesis produces a short map: direct references, inferred consequences, scope gaps and a safe next action. The Skill is read-only; it never moves, renames, deletes, shares or claims a move is safe merely because no reference was found. It asks for authorization when the target is outside scope. The actual Skill is [impact-rehearsal/SKILL.md](../prototype/impact-rehearsal/SKILL.md).

## 5. What actually happened

Two fresh concept-probe Codex processes inspected separate fictional 12-file text archives. In the [impact probe](../experiments/11-ai-native-nas/concept-probes/outputs/impact/raw-response.md), a cover file was directly referenced by an Autumn program and Winter draft, and an external print partner was unchecked. The model advised leaving it in place while examining the references. In the [rebuild probe](../experiments/11-ai-native-nas/concept-probes/outputs/rebuild/raw-response.md), the model created a four-section River Walk handout and noted missing photo permissions and uncertain printer/venue. The latter contains a capitalized source quote that is not byte-exact. Both are local Codex outputs, not UGREEN agent responses or real-user validation. [Probe audit](../experiments/11-ai-native-nas/concept-probes/README.md).

The official static checker returned **`static-pass`, exit 0, zero errors and warnings** for the new Skill, SHA-256 `76a8beac3760769dfea56ce6a6f1cca1aa511e5472b72cc13d210d3228aa092d`. Initial heading, placeholder and mapping format errors were corrected; the final check was repeated. Static success does not confirm installation, source returns or execution on the assigned NAS.

For the [compact comparison](../experiments/11-ai-native-nas/mvp-results.md), a generic agent and Skill-guided agent used equivalent fictional data and scopes on normal, missing-target and authorization-limited cases. Both found the key normal-case references, qualified incomplete evidence and avoided a move. Initial guided output did not explicitly request permission for the inaccessible target; the Skill was amended and a new guided run did so. The generic response also acknowledged that broader inspection required authorization. These are one-shot local trials with an unblinded author and a revised second wave, not evidence the Skill is generally more reliable or saves user steps.

A mechanical audit normalized the temporary mount/line suffixes and found all 40 cited underlying fixture paths existed. Raw Markdown citations are **not portable clickable links** from saved reports: temporary mount paths vanish, and relative paths with line suffixes are not established as valid from the output location. Accurate source identities, exact quote checking and incomplete coverage on real NAS remain unresolved.

## 6. Judge demo and critique

The [three-minute storyboard](../research/11-ai-native-nas/judge-demo.md) begins with “Before I move this cover, what might that affect?” The planned reveal shows two real returned project references and an unchecked external partner; the owner receives a review step and nothing is moved. Only the local model experience and static check exist today. Final-round video must show actual UGREEN device operation; if expert results cannot support citations, show the gap rather than inventing a working demonstration.

A NAS owner might value preventing a broken project; a hypothetical UGREEN team might value an appliance that explains consequences of changes. But an engineer can reasonably say this is ordinary search and a prompt. The closest competition includes in-app link updating, Adobe's media relinking and code refactoring previews; [ClaimReady](https://devpost.com/software/claimready-home-inventory) is a public UGREEN entry for a different evidence/inventory outcome, while the official gallery and Skill Hub remain incompletely accessible. Full [competitive critique](../research/11-ai-native-nas/competitive-critique.md). No credible claim of global novelty has been established.

## 7. Decision, risks and next action

**REDESIGN**, not GO. The experiment met the request to build and statically check a plausible Skill prototype, but it has not shown exceptional user appeal or a clear advantage over the built-in assistant. The key NAS risk is that actual registered experts may not return stable source paths, excerpts, complete coverage or resumable waiting states. The key safety risk is a partial scan being mistaken for a complete dependency graph. We did not run optional self-optimization: it adds no demonstrated value to this MVP, requires reliable held-out evaluation and cannot be assumed to run within the Skill.

**Next action:** obtain one real UGREEN file/document/knowledge expert-return sample or run one bounded device test when access is available, then show the same preview and generic baseline to real NAS owners. Verify actual source references, an inaccessible target, external dependency disclosure and user preference. The [anonymous concept packet](../experiments/11-ai-native-nas/concept-probes/human-packet/participant-packet.md) is prepared for exploratory feedback; no one has been contacted. If real users find the interaction generic or the expert outputs lack usable provenance, choose the Rebuild Kit fallback or return to ideation.
