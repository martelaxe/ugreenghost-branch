# Experiment 14 decision — cold-start Task Continuity

**STOP developing Task Continuity as a standalone hackathon entry.** A fresh AI can continue useful work from a saved Markdown handoff, and the handoff preserved a preference that existed only in the first conversation. But the generic agent given the same record and draft handled the scenarios substantially as well as the specialized Skill; close existing Markdown handoff Skills already describe the same experience. This experiment has not established a credible differentiating product benefit beyond ordinary saved context. The skill also has two concrete local reliability defects: nonportable raw citations and an incorrect file count in one repeat. This is a decision about the standalone entry, not proof that handoffs are useless.

## What actually happened

The original fictional task was to draft an event invitation and volunteer handoff. The first user additionally chose bilingual English/Spanish and the exact English tagline “Repair together, waste less”; that preference existed only in the first conversation. After an initial strict-isolation routing failure and a second attempt whose file tool was unavailable, a new local Codex producer actually read 25 documents and generated a [bilingual invitation and handoff](../experiments/14-task-continuity/producer/initial-deliverable.md) and a [source-linked capsule](../experiments/14-task-continuity/producer/capsule.md). A local adapter wrote the exact generated blocks to files; no UGREEN save or platform approval occurred. The producer's “no files saved” statement was true when the output was generated, before that adapter wrote local copies.

Nine fresh successor Codex processes ran: G0 without the saved record or prior draft; G1 with both; S with those same files plus the exact frozen Skill. No previous chat or logs were intentionally given. Known project and history paths were masked; configured runtime and other host paths were available, so isolation is not absolute. Captured tool calls show only fictional workspace reads. Raw outputs, prompts, event logs, manifests, hashes and measured wall times are in [model results](../experiments/14-task-continuity/model-results.md).

- In the normal case, G1 and S retained the bilingual format and tagline; G0 had no access to that earlier-only choice and was not penalized for missing it. The result shows **retained information helps**, but G1/S got both a capsule and a draft, so the experiment does not isolate the capsule from the draft.
- When the venue document changed from 10:00–13:00 to 11:00–14:00 while the volunteer timetable still listed old times, G1 and S used the current venue record and flagged the outdated handoff and conflict. G0 noticed the current source conflict but could not compare a record it was not given.
- When `rights/` was unavailable and excluded from the new scope, G1 and S did not treat old rights claims as currently verified. They attributed the new toilet-location report to the user, not an independently checked venue document. In a separate malicious-record test, both rejected an unsupported claim of prior dispatch and ignored an instruction to override the current user.
- No method proved it saved time or avoided re-reading sources. In this small local sample, S used three shell-tool commands in each scenario and G1 used two; concurrent-run elapsed times do not establish general efficiency or cost.

## The meaningful failures

All **133 raw Markdown links** across the nine saved successor reports failed to resolve from their saved report locations; all 133 mapped back to actual retained fixture files after normalizing temporary paths and line suffixes. A research-only host adapter produced separate `response-portable.md` copies whose 133 links resolve; it is not a UGREEN feature and does not alter raw outputs. The capsule's own 27 links resolve when placed with A/B sources; three rights links intentionally do not resolve in restricted C.

A separate repeat using the exact frozen Skill reported **26 non-handoff source files**, but its fixture had **25**. This is an incorrect coverage count. In several S invitations, the user-reported toilet location appears in public copy with its provenance in a footnote; copying the sentence alone could lose that qualification. Neither limited trials nor local tests establish general prompt-injection resistance, user preference, semantic correctness of all claims, or reliable production state handling. [Evaluation](../experiments/14-task-continuity/evaluation-results.md) and [exact Skill validation](../experiments/14-task-continuity/final-skill-validation.md) record the outcomes; eight deterministic integrity checks passed.

## Official capabilities and limits

The installed catalog documents `file-agent` reading/listing/path inspection, `document-agent` extraction and QA, and `knowledge-agent` `save-text` with workflow approval. It is plausible to save a Markdown record, explicitly provide its path in a later conversation, reread it and recheck authorized sources. The catalog does **not** establish automatic discovery, persistent cross-session model memory, atomic no-overwrite, resumable waiting/approval, stable citations or exact expert result propagation. A later revision needs a genuinely safe and approved new path; a stored record grants no permissions. [Platform feasibility](../research/14-task-continuity/platform-feasibility.md).

The new Markdown-only [task-continuity Skill](../prototype/task-continuity/SKILL.md) remained frozen throughout baseline and repeat tests. Official static checker: **exit 0, static-pass, 0 errors and 0 warnings**, SHA-256 `31f80d61b6ffa5746f00eba0e00f39837f21201cfde1f62191330477bbe095e9`. This is a structural check, not UGREEN runtime evidence. No real save, approval, device execution, or cross-conversation NAS session occurred.

## Originality, judges and fallback

[Session Handoff](https://github.com/crd/session-handoff) already describes Markdown records containing decisions and artifacts plus continuation with stale-state checks; [Handoff Skill](https://github.com/jumpifequal/handoff-skill) describes portable provenance and cross-model continuation. [LangGraph](https://docs.langchain.com/oss/python/langgraph/persistence) documents checkpointed and cross-thread memory, while [Nextcloud Assistant](https://docs.nextcloud.com/server/stable/user_manual/en/ai_assistant.html) provides file-aware AI and Skills. These comparisons are based on public documentation, not a hands-on comparison. They make a broad claim of novel continuity indefensible. An author-only subjective assessment is 17/25 User Value, 5/25 Innovation, 12/25 Technical Quality and 9/25 AI NAS Fit; these are not official judge scores.

A judge would see a fresh agent recover an earlier preference and catch a source mismatch. That is understandable, but generic Markdown handoff already provides the core experience, the user must locate a record manually, and actual UGREEN saving/permissions remain unverified. The concept is useful, but insufficiently differentiated for the stated creative-award goal. The [planned demo](../research/14-task-continuity/judge-demo.md) is only a plan, not device footage.

**One next step:** stop iterating on Task Continuity as the entry and investigate a concrete user-visible NAS outcome that cannot be replicated simply by supplying the same Markdown record to a generic assistant. **One fallback for exploration:** return to Experiment 12's Project Rescue as a narrow action-oriented candidate, contingent on real confirmation of collision-safe approved copying; it is not yet selected for submission and faces its own relinking competitors.

The [official rules](https://ugreenhackathon.devpost.com/rules) set the Round 1 deadline at November 15, 2026, 11:45 p.m. Pacific. No final submission PDF or ZIP was made, no Skill was published, and no external participants were contacted.
