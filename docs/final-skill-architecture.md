# Before You Move — architecture

**Selected:** fallback flagship. One user decision: assess a proposed move, rename, deletion or consolidation before acting. The technical package directory and frontmatter name are `final-flagship` to satisfy the checker; the user-facing product identity is **Before You Move**. No skill is installed on UGREEN, and the architecture is a Markdown instruction workflow, not a deterministic engine.

**Modes:** (1) impact review on the selected target and intended change; (2) copy-role comparison for explicitly selected copies the user proposes to consolidate. The second mode serves the same pre-change decision; it is not whole-drive cleanup. Both finish with a sourced preview and one next step. They perform no writes. A read-only report is the substantive result; it must be judged on whether it helps avoid an actual mistake, not on its length.

**Flow:** capture owner-provided target/action/destination when needed and authorized roots → file expert bounded discovery → document expert analyzes selected actual references → optional knowledge expert tests a specific unsettled claim → optional file expert checks selected hashes → parent synthesizes observed direct relationships, less certain matches, contrary evidence, limitations and next step. Repeated requests start a fresh investigation, without cross-session state assumptions.

| Owner | Actual documented action | Request | Limitation |
|---|---|---|---|
| `file-agent` | `ug-filesystem:find`, `ls`, `stat`, `cat`, `sha256sum` | scoped `path` and applicable documented filters/limits; individual selected paths for hashes | Exact return envelopes, stable paths, complete enumeration and read scope not guaranteed. Hash equality is byte identity evidence only. |
| `document-agent` | `ug-document:qa`, `reconcile` | `qa` requires `query`; pass actual selected `file` inputs and task | Format support, excerpts and source references unverified on hardware. |
| `knowledge-agent` | `ug-knowledge:collect-evidence` | `query`, actual optional `path`/filters | Parent requests both support and contrary evidence; if return lacks source or material, unknown. |

The parent delegates only to registered experts; it constructs requests from actual scope/limits and completed results. The catalog labels these selected operations read/no platform action approval. **Read access still needs appropriate user authorization.** Later writes are out of scope and require a separate expert workflow and approval. Neither read request limits nor safety instructions enforce a deterministic budget.

**Evidence handling:** preserve original source path and excerpt if actually returned; classify direct path, name-only ambiguity, historical context, conflicting evidence and unknown. Distinguish discovered, selected and read only if returned. Empty results never prove absence. Partial or absent results stop dependent steps. Confidential material is not unnecessarily propagated; storage on a NAS does not guarantee local-only model processing. Exact matching shows the referenced words/path, not that runtime use or harm is proved.

**Why use it:** invocation compression and a reusable conditional procedure that integrates change-specific evidence and, on request, copy identity/role review. Generic Uliya with the same capabilities can do this and was competitive in local testing. No independent user-time, generic-Uliya or safety advantage has been established. The actual first-party File Search and File Organization experiences are also important competitors.

**Known failure boundaries:** no documented live app dependency graph, ACL audit, snapshots/restore, historical version API, automatic monitoring, result pagination/completeness, rollback, approval resumption or atomic no-overwrite. Device expert source attribution and cross-agent handoff remain unverified. The official static checker checks structure, not performance or hardware.
