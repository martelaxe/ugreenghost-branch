# Experiment 12 decision: Project Rescue

**REDESIGN.** The strongest action-oriented direction is a narrow Project Rescue: find a copy of a missing project asset, explain evidence and a shared-file dependency, obtain approval for one non-overwriting copy, and verify source and destination. A local fixture demonstrates the storage change; the official catalog documents potentially suitable agents and operations. The decisive behavior—safe copy, real approval and verification on UGREEN—is not yet verified, and the differentiating value over app relinking or generic agents remains uncertain. **Primary: Project Rescue. Fallback: the previous read-only Impact Rehearsal**, honestly described as a preview if write safety cannot be established.

## What UGREEN documents

The [starter kit](https://ai.ugreen.com/pages/hackathon-starter-kit) describes expert Skills and approval before file changes. Installed catalog 2.0.0 documents file-agent `ug-filesystem` read/list/stat/hash and `cpmv` with `type=copy|move`, optional overwrite and gateway approval; `mkdir`, rename, delete, file tags and workflow-approved batch operations are also listed. Document-agent provides extraction and comparison; photo-agent provides approved album creation; knowledge-agent can save text with workflow approval. See the [78-action audit](../research/12-self-healing-archive/action-capability-audit.md). CLI result summaries and expert return shapes are not equivalent guarantees. Catalog operation presence does not prove hardware works.

A read → plan → user and platform approve → copy → readback workflow is **compositionally documented**, not runtime verified. In particular, whether the target's no-overwrite semantics are atomic and enforceable, how exact path parameters are interpreted, what expert responses contain, whether approvals resume and whether the parent receives enough evidence are open questions. A check immediately before writing cannot by itself close the race. If safe no-overwrite cannot be ensured, the Skill must stop. `restore` does not establish automatic rollback.

## Product and why someone might want it

A creator asks: “Find the missing Harbor cover and restore one matching copy without disturbing the other project.” In the strongest proposed 90-second demo, a project manifest names an absent file and expected hash, a shared candidate matches, and another project references the shared original. With explicit approval and demonstrated platform no-overwrite, copy one item to the expected location; verify both hashes and the original path. The emotional reveal is that a missing working asset reappears without moving the file a second project uses. One expected path restored is not proof that the entire application/project works.

Users report [anxiety about removing duplicates](https://www.reddit.com/r/DataHoarder/comments/1ftktdv) and [identical paths used by applications](https://www.reddit.com/r/DataHoarder/comments/1i6unmb/i_knew_i_had_some_duplicate_files_but_had_no_idea/); an [Immich issue](https://github.com/immich-app/immich/issues/18792) illustrates that album membership may be significant beyond matching bytes. These are individual reports, not population estimates or user validation. [Adobe Premiere Link Media](https://helpx.adobe.com/premiere/desktop/organize-media/file-organization/locate-and-link-offline-files.html) already reconnects missing media; its [automatic relink](https://helpx.adobe.com/premiere/desktop/organize-media/ingest-proxy-workflow/relink-offline-clips.html) is a strong direct competitor. Generic Codex identified the same synthetic match and protected dependency. Claims of global novelty or superiority would be misleading.

## What was actually built and tested

- A 26-file fictional archive, separately frozen answer key, initial manifest, 8 successful local model planning trials (generic and Skill-guided across 4 cases) and 8 retained initial trials whose file access failed due to missing `bubblewrap`. See [MVP results](../experiments/12-self-healing-archive/mvp-results.md).
- A research-only Python adapter copied `shared/review_17.txt` into the missing Harbor path on a disposable fixture with synthetic approval inputs and OS exclusive creation. It verified equal SHA-256 and source preservation, with one added path and no modified or removed originals. [Before/after](../experiments/12-self-healing-archive/local-demo/before-after.md). This was local Python, not NAS execution or real approval.
- Ten deterministic local tests passed: approval absence, destination collision, changed/missing source, unavailable destination, write failure and failed readback among them. The failure case reports `unverified` even though a copy had occurred. These tests do not certify UGREEN enforcement.
- Both general and guided model responses found the intended evidence, protected the shared path, requested permission for the unavailable source and kept a failed verification uncertain. S added explicit platform/no-overwrite/undo distinctions in this small sample. No repeatable advantage, user preference or statistical improvement has been shown; prompt scope was not OS-enforced. Important source paths were checked; citations are not automatically portable links.
- A Markdown-only [Skill prototype](../prototype/project-rescue/SKILL.md) uses file-agent and document-agent, not direct parent CLI or custom code. Official checker: `static-pass`, exit 0, 0 errors/warnings, SHA-256 `44425ef3559d2679c24ad02f20587832bdf22e29338fb4ed8a2519c40d22b071`; static validation is not device verification.

## Assessment and next action

The MVP hints at the larger vision of preserving project context during storage operations; it is useful only if identity and safe copy can be established. It cannot guarantee general dependency detection, app repair, undo, proactive monitoring or privacy of an unspecified model. The biggest reasons for rejection are that the exact demo resembles Adobe's relinking and a generic agent/manual copy, and the key UGREEN write behavior is unknown. One-day device demonstration is plausible only if real expert results carry evidence, platform approval works and collision-safe copy is supported; [plan and fallbacks](../research/12-self-healing-archive/one-day-nas-plan.md).

**Single next action:** obtain authoritative confirmation or a bounded real-device test of `cpmv` copy destination semantics, enforceable no-overwrite behavior, explicit gateway approval and readback evidence on a disposable fixture. If unavailable before selection, prepare a truthful Round 1 feasibility statement and test this first in the finalist window; do not promise automatic repairs. The [official rules](https://ugreenhackathon.devpost.com/rules) set Round 1 to November 15, 2026, 11:45 p.m. Pacific and do not require NAS evidence then; Round 2 requires a working device Skill and footage.
