# Final flagship decision — Before You Move

**FALLBACK FLAGSHIP.** We selected and authored a UGREEN-format read-only Skill that helps an owner review likely references and copy roles before a proposed move, rename, delete or consolidation. It answers the user's recent question about surprising relationships among stored files, while avoiding unverified atomic copy semantics. The package encodes a useful procedure; it does not create a new filesystem primitive or establish superior intelligence.

## Why this selection

[Inventory](../research/final-selection/01-complete-candidate-inventory.md) covers earlier discovery, creative, history, continuity, rescue, storage optimization and verification directions. [Ranking](../research/final-selection/02-ranking-and-selection.md) compares them using four equally weighted dimensions. Project Rescue is more tangible but its desired final action depends on unverified atomic no-overwrite and approval. Creative Salvage is more imaginative but its main idea was found by generic Codex and real creator value is unverified. Before You Move's primary result is feasible as a read-only evidence preview if real expert handoffs work. Native search, official file organization, and a generic assistant remain strong competitors. The narrow optional copy-role branch combines byte identity and context in the same pre-change decision, rather than adding unrelated features.

## What was built

[Skill entry](../prototype/final-flagship/SKILL.md) and three directly linked Markdown references describe scoped discovery, relevant document reading, optional targeted contrary evidence, optional selected copy hashes, observed/ambiguous/historic/unknown classification, bounded scope, failure states, user authorization and no write actions. Its formal Skill ID is `final-flagship`, matching the requested directory; the user-facing identity is Before You Move. [Architecture](final-skill-architecture.md), [decision table](final-skill-decision-engine.md) and [demo plan](final-flagship-demo-storyboard.md) explain the implemented instructions and limitations.

The [official checker](../experiments/final-flagship-tests/static-check.json) passed with zero errors and warnings after correcting documented initial structural failures. This proves only static compatibility. No execution occurred on UGREEN NAS, no child expert was invoked, and no actual device approval or source-return contract was validated.

## What happened in tests

Four initial read-only Codex runs could not execute any inspection because `bwrap` was unavailable. We preserved those honest failed investigations. Eight fresh local Codex processes retried two normal and two edge cases on disposable fixture copies with task-instructed read-only scope but without OS-enforced isolation. Both baseline and Skill identified the key direct-reference and equal-bytes/different-roles results; both preserved ambiguity. In the restricted case the guided result additionally noticed that a generic “card” reference could refer to the target; the baseline's narrow keyword search missed it. All reports were returned and no fixture bytes changed. These are four pairs of one-shot model responses, not evidence of general superiority. The model name was not explicitly fixed in the logs. Full traces, failure caveats and counts: [test results](../experiments/final-flagship-tests/test-results.md).

Twelve deterministic tests passed against a separate research-only mock policy model. That model was not executed by the Skill and does not stand in for UGREEN agents. The user's requested missing-file, real incomplete agent output, actual approval, same-session rerun and large-collection behaviors remain untested on device.

## Skeptical reviewers (author analysis, not simulated or real external judges)

- **Ordinary NAS owner:** “I can ask the built-in assistant this. Why install another Skill?” The strongest answer is a shorter invocation and a reusable role/impact procedure. Neither time saved nor user willingness to install has been measured. Give a one-line request and a specific, minimal decision result; do not require mandatory three-expert calls.
- **UGREEN engineer:** “Your catalog entries do not guarantee complete listings, usable citations or child-to-parent mapping.” The package now specifies actual paths/results only, unknown coverage, and failure/waiting branches. Real hardware validation is still the principal technical gate.
- **Hackathon judge:** “The result looks like a careful search report; your own generic baseline found the same thing.” This is the strongest creativity objection. One restricted synthetic case showed an additional qualified detail, not reliable competitive differentiation. Do not claim innovative storage technology or a proven model advantage.

Subjective internal estimates out of 5 (not actual judge scores): User Value **4**, Innovation & Differentiation **2**, Technical Quality **3**, AI NAS Fit & Validation **3**.
