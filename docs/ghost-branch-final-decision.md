# Ghost Branch — final decision

**SUBMIT WITH RESERVATIONS.** Ghost Branch has a clear developer-focused problem, a coherent three-mode investigation and recovery-packet workflow, an official-format Markdown package and a truthful Round 1 draft. It is plausible under the documented expert architecture, but its real NAS handoffs and its competitive differentiation remain unproven. The user requested this concept; no alternative was substituted.

## What it does

A developer authorizes a current snapshot and old backups. The Skill is designed to discover plausible historical work, look for existing current equivalents and reasons against revival, and prepare a source-backed packet for a developer or coding agent. The NAS supplies off-repository materials, but the Skill does **not** run Git, know whether a directory is a valid repository, prove something was uncommitted, compile or test code, create a real branch or modify a project. Its four advisory categories are RECLAIM CANDIDATE, RETIRED FOR A REASON, UNCERTAIN and NOT ESTABLISHED.

## Actual local evidence

A 21-file fictional Lantern Ledger archive provides: (1) a CSV export renderer, an internal pilot and a visual mock; (2) a remember-browser experiment with a stored review saying its localStorage design was removed; and (3) old title-filter code whose behavior appears in the current snapshot under a different path. These are fixture facts, not real developer history or evidence that Git actually missed work. The separate report service is intentionally unavailable. See [fixture](../experiments/ghost-branch/fixtures/lantern/) and [ground truth](../experiments/ghost-branch/ground-truth/answer-key.json).

Twelve initial fresh local Codex processes covered four investigations under generic short, generic detailed and Skill-guided conditions. All three approaches found the three intended central findings. The original Skill's focused-export answer over-associated an intermediate failure log with a specific source file; the log did not name the file. We fixed that precise rule and repeated discovery and export across all three conditions, six more processes. The revised Skill stated the source/log linkage was unknown; the detailed generic answer also did so. A three-process synthetic `.env` canary probe showed that the short generic agent read a dummy value into its **tool trace**, while detailed and Skill agents did not; none put it in their final answer. These one-shot synthetic trials do not establish general superiority or a security guarantee. Total 21 local processes completed successfully with fixture contents unchanged. [Full test report and raw outputs](../experiments/ghost-branch/test-report.md).

Important remaining defect: the revised Skill-guided discovery report had only **1/14** Markdown links resolving from its saved report location at audit time, and the focused report had **0/14**. Underlying file identifiers mapped to known fixture paths, but generated `:line` suffixes/relative paths were not portable. Actual UGREEN reference rendering remains unknown. [Portable, human-curated recovery packet](../experiments/ghost-branch/ghost-recovery-packet.md) provides a reviewable artifact; it is not the exact Skill-generated text or a NAS file.

The local agents used instruction-limited, unrestricted disposable workspaces, not OS-enforced isolation; no actual project code or tests were run. The 17 deterministic checks exercise a separate local mock policy model, not the Skill or UGREEN experts. No real developer evaluated usefulness. Real NAS expert output, source formats and provenance, search completeness, screenshot analysis, approval resumption, safe no-overwrite saving and large-archive performance are unverified.

## Official checks and submission materials

The final [Skill](../prototype/ghost-branch/SKILL.md) and four directly linked Markdown references passed the official static checker: **static-pass, zero errors and warnings**. This is not proof of NAS execution. The draft [proposal PDF](../submissions/round1-ghost-branch-draft/ghost-branch-proposal.pdf) contains 297 English words across ten answers and is 3,945 bytes. The [Skill ZIP](../submissions/round1-ghost-branch-draft/ghost-branch-skill.zip) is 8,286 bytes with five allowed Markdown files; its hashes match the checked files. [Verification](../submissions/round1-ghost-branch-draft/package-verification.json), [submission checklist](../submissions/round1-ghost-branch-draft/README.md).

Internal 0–5 judgments, not judge scores or probabilities: User Value **3**, Innovation & Differentiation **2**, Technical Quality **3**, AI NAS Fit & Validation **3**. [Three-perspective adversarial review](ghost-branch-competition-review.md). A user must verify eligibility, ownership, AI disclosures and the competition's rule about developing the Skill and core workflow during the event before submitting. Round 1's lack of NAS runtime evidence does not by itself reduce eligibility or score according to the [official rules](https://ugreenhackathon.devpost.com/rules).

No Skill was installed, uploaded, published or submitted, and no prior work was overwritten. The proposal and ZIP are ready for human review; finalist hardware testing, not this local experiment, must establish actual operation.
