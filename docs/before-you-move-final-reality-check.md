# Before You Move — final value and truthfulness test

**Final recommendation: DO NOT RECOMMEND** as the hackathon entry on current evidence. The Skill could package a helpful procedure for repeated use, but the actual comparisons did not demonstrate a distinctive capability or an advantage over a carefully prompted generic assistant. It is not realistic to claim a strong innovation story from these observations. This is a decision about our demonstrated case, not proof that every user would find the Skill useless or that another AI could never benefit from it.

## Exact outcomes

Three fictional datasets, three matched approaches, nine fresh Codex runs: ordinary short request, detailed generic procedure, and the complete original Skill. Each condition got the same case-specific user request, fixtures, intended scope, local tools, explicitly requested model and safety conditions. All completed with zero exit status and unchanged fixture hashes. Four separate claims matter:

1. **Identical copies with different roles:** all three checked equal content, found `active/manifest.md` referencing `active/assets/badge.svg`, found `archive/retention.md` preserving `archive/assets/badge-snapshot.svg`, and avoided recommending immediate deletion. The detailed and Skill reports both suggested verifying the decision with the relevant owner. The core discovery was not Skill-specific. [All responses](../experiments/before-you-move-reality-check/runs/copy_roles/).
2. **Ambiguous dependency:** all three found the direct press index and correctly qualified whether the launch poster used `press/assets/logo.svg` or the different same-name workshop file. The ordinary and detailed agents also inspected both SVG contents; the Skill identified the alternative but did not establish its different content. The essential ambiguity remained correct in every response. [All responses](../experiments/before-you-move-reality-check/runs/ambiguous/).
3. **Incomplete authorized scope:** all three acknowledged that other project folders were unreviewed and saw that `visible/archive/` did not exist. The ordinary answer stated uncertainty without a specific next review; the detailed prompt suggested an authorized review of those folders. The original Skill suggested checking the draft and destination but did not explicitly request permission to inspect the other folders. [All responses](../experiments/before-you-move-reality-check/runs/partial/). This is an excluded-scope case, not a real truncated NAS search.
4. **Targeted revision and rerun:** the new Skill references require per-copy path, evidence and role where returned, and a concrete request for targeted access or user-provided evidence when an excluded area could resolve a material unknown. In three new fresh matched runs of the **same** limited-scope fixture, the revised Skill requested that authorization or evidence, while the detailed generic answer also called for an authorized review. This was an exploratory post-fix recheck of the same fixture, not a new holdout or general reliability proof. [Revised Skill response](../experiments/before-you-move-reality-check/runs-postfix/partial/skill/response.md).

No tested report recommended an immediate destructive action, and no fixture bytes changed. That does not prove safety: runtime access restrictions were instructions rather than OS-enforced isolation, only one response per condition per case was used, and this is not a UGREEN device test. Source links often use temporary host paths rather than proven Uliya citations. See [detailed results, prompts, commands and full raw responses](../experiments/before-you-move-reality-check/results.md).

## Value and effort

The ordinary user requests were 15–27 words and stayed identical across all conditions. The detailed generic procedure added 113 words; a Skill could prepackage comparable instructions. In the first nine runs, ordinary/detailed/Skill used respectively **2/2/2**, **3/2/2**, and **2/3/3** local shell commands across the three cases. The detailed agent unnecessarily hashed four visible files in the limited-scope example where no copy comparison was requested; the ordinary and Skill conditions did not. A shell command can perform many file operations, however, and none of these are measured UGREEN calls or hardware performance. No interactive clarification or approval was completed during these local runs, and no real user time or willingness to install was measured.

The final revised output improves an actual, specific next step, but the generic detailed condition already showed how to get that result. The plausible value of the Skill is reusable **instruction compression and a consistent format**, not a demonstrated novel operation or reliably superior reasoning. A repeat user might like it; our evidence is insufficient to recommend installing it as a product.

## Claim review and changes

The [claim audit](../research/before-you-move-reality-check/claim-audit.md) examines every substantive part of the Skill and all ten proposal answers. The revised Skill asks for actual returned evidence, qualifies partial scope and cannot assert safety or complete dependencies. The revised PDF uses “designed to,” “requests” and “aims to” where actual UGREEN operation is unverified, and explicitly states that generic AI with a detailed prompt produced similar findings. It does not claim a measured superiority, complete references, guaranteed privacy, or actual NAS execution.

The two policy changes are in a **new** [revised Skill directory](../prototype/before-you-move-final/final-flagship/); earlier prototypes and drafts are preserved. The official checker returned **static-pass, zero errors and warnings** on the revised directory. [Static result](../experiments/before-you-move-reality-check/static-check-revised.json). Static checking cannot confirm installation, expert returns or reliable execution.

The Skill's actual expert handoffs, returned source paths and excerpts, coverage, permissions, configured model/data processing, and behavior on a real UGREEN NAS are unverified. The provided cases were synthetic and small; no users judged the outputs, no actual truncated listing was tested, and the revised Skill was tested on only the repeated limited-scope case. Eligibility and the rule requiring the submitted Skill and core workflow to be newly developed during the competition still need human review. No project was published, submitted, committed or pushed.

**Competition implication:** a reusable pre-change checklist is potentially useful, but our tests show that generic AI—especially with a detailed request—already delivers essentially the same central outcome. We cannot support a credible claim that this is a substantial new interaction or substantially better result. Given the user's stated priority on value and differentiation, the evidence does not justify recommending it as the final entry.
