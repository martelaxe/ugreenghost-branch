# Experiment 13 decision — Task Capsule

**REDESIGN.** The useful insight is that a NAS can help turn scattered source material into an actual task deliverable and expose decisions rather than forcing the user to build folders first. The strongest narrow candidate is **Decision-Ready Task Capsule**: assemble a usable text artifact and a compact evidence-and-decision handoff, optionally save it after a separate approval. It is a prototype of a possible bigger “Taskspaces” vision, not a new operating system, task manager or persistent agent. **Primary: Task Capsule. Fallback: the existing read-only Impact Rehearsal** when a concrete evidence-based impact preview is preferable. Do not combine these into an unbounded general-purpose assistant.

## User and competitive reality

Scattered records and documentation appear in individual [self-hosted user discussions](https://www.reddit.com/r/selfhosted/comments/1amlb9i), but those anecdotes do not prove that people want a generated task layer. The real underlying need may be getting a useful result, maintaining evidence and avoiding extra organization. [Nextcloud Assistant](https://docs.nextcloud.com/server/stable/user_manual/en/ai_assistant.html) already provides contextual AI and file-based Skills; [Paperless-ngx](https://docs.paperless-ngx.com/usage/) offers classification, workflows and multi-document chat; [Synology Office AI](https://kb.synology.com/index.php/en-us/DSM/help/Spreadsheet/doc_ai_integration?version=7) drafts with file references. Our exact cross-file handoff is not shown to be absent in those products. A [July 2026 filesystem-memory study](https://arxiv.org/abs/2607.26637) reports cheaper retrieval for some large organized stores but not better answers from organization alone; its measurements do not validate our small fixtures.

## What was built

Fifteen local Codex trials tested general G, minimal M, and task-context T contracts across tax organization, monthly report, review package, a historical event and a future-dated event. They inspected 10–12 fictional files per archive and produced complete text outputs. Both generic and specialized outputs handled the main facts; no speed, preference, statistical reasoning gain or advantage from persistent context was established. `comparison-results.md` preserves their exact prompts, logs and results. Strongest tangible artifact: the [2027 event invitation and volunteer handoff](../experiments/13-taskspaces/wow-case/future/runs/T/response.md), which combines a correct current date/venue with a photo-use hold and outstanding accessibility and organizer decisions. The graphic is described in text, not an actual tested image.

The historical version revealed the event date had already passed; all three models correctly flagged it rather than silently inventing a date. We preserved that case and added a separately versioned future fixture. The tax T output flagged a $40 discrepancy but did not clearly note that the bank entry does not name INV-10; M did. This is a real unresolved inference and shows extra task structure did not eliminate risk. In C all three models read and did not obey a destructive prompt-injection example. A final-Skill exposure test also ignored it, but this is not a general security guarantee.

A separate local Python analogue created one fictional folder and copied one receipt while preserving all originals and checking hashes. It used synthetic approval inputs, not a real person or UGREEN gateway. The CLI also saved model responses locally; no NAS save, write, approved action or expert result occurred. Main outputs have 319/319 resolving local links; five robustness outputs have 39/39 links broken because temporary workspaces were deleted. This distinction prevents a false claim that citations are generally portable. Local deterministic event tests passed 12/12; those are test cases, not UGREEN runtime enforcement.

## Official capability and Skill boundary

The installed catalog documents file-agent discovery and reads, document-agent extraction, and knowledge-agent `save-text` with workflow approval. Optional file-agent readback can inspect an actual returned path, but save semantics, source-return fields, collision behavior, approval handoff and verification are not established on real NAS. A Markdown record is a possible approved file save, not a persistent task identity, ongoing monitor or automatic resume. [Capability contract](../research/13-taskspaces/capability-contract.md); [prior 78-action audit](../research/12-self-healing-archive/action-capability-audit.md).

The Markdown-only [task-capsule Skill](../prototype/task-capsule/SKILL.md) coordinates these agents, bounds scope, handles untrusted prompts, and produces a usable result with decisions and evidence. It asks before optional saving and stops if no-overwrite cannot be assured. Official checker: exit 0, `static-pass`, 0 errors/warnings; SHA-256 `e421de0d29e6521775e0af142cad4128255277d2f44c5a5b60cc16642473efe7`. Static validation does not confirm actual NAS behavior. Output does not install or execute archived prompts.

## Judge simulation and honest product assessment

Three fresh independent Codex reviewers with different perspectives reviewed anonymized output and actual sources. Their subjective scores were 57–67/100; innovation was 9–11/25. Product preferred the T output, while engineering and creativity preferred minimal M. They agreed the results were useful but close to existing file-aware assistants, with NAS execution unverified. One reviewer invented a headline that was not in the source output, and another correctly identified links broken in the relocated review packet but incorrectly generalized that issue to original artifacts; these errors limit the simulated reviews. See [judge simulation](../research/13-taskspaces/judge-simulation.md). Scores are not official judging or human validation and did not select the prototype.

The event pack is not a spectacular new interaction: a generic agent produced nearly the same deliverable. A judge could reasonably reject the entry as a prompt that combines summarization, citations and permission reminders. One repeatable useful result is not evidence that people want another organization layer. This is why the recommendation is REDESIGN despite a credible minimal Skill and usable local artifacts. The most consequential technical uncertainty is whether real agents return stable references and whether `save-text` can safely save and be independently verified after approval.

A truthful three-minute device demonstration would show one authorized task, real expert-returned source references, an editable invitation and handoff, an unresolved photo/accessibility decision, and an actual optional save only if explicitly approved and independently verified. If not, show a chat draft and say no file was saved. The [official rules](https://ugreenhackathon.devpost.com/rules) require Round 1 PDF and initial Skill ZIP by November 15, 2026 11:45 p.m. Pacific; no device evidence is required for Round 1, whereas a real device Skill and footage are required in Round 2. Nothing was packaged or published.

**Single next step:** conduct a blinded, task-based walkthrough of the general-agent and task-capsule event outputs with one willing NAS owner or organizer, using the prepared [human evaluation protocol](../experiments/13-taskspaces/human-evaluation.md). Determine whether the capsule materially improves completing a real handoff, rather than assuming structure helps. No one has been contacted. If people see no meaningful difference, narrow or change the concept; independently verify actual expert and save semantics during any assigned NAS session.
