# Prior art and competitor challenge

Reviewed 2026-10-27. Links are to primary documentation except the research papers; coverage is targeted, not an exhaustive product survey. An undocumented feature is **not** evidence the feature is absent. No claim of worldwide novelty.

| Proposed operation | Closest reviewed prior art | Accurate overlap and remaining possible contribution |
|---|---|---|
| 1 Progressive reconciliation | [rclone check](https://rclone.org/commands/rclone_check/), [rsync](https://rsync.samba.org/ftp/rsync/rsync.1) | Nearly same core functionality already exists; rclone compares matching paths using supported size/checksums, rsync's quick check and checksum modes are distinct. A Skill might expose a convenient adaptive explanation or measurable optimization; it does not invent reconciliation. |
| 2 Coverage-first discovery | [QNAP Qsirch](https://www.qnap.com/en/how-to/tutorial/article/qsirch-the-quick-start-guide), [Spyglass](https://www.usenix.org/legacy/events/fast09/tech/full_papers/leung/leung.pdf) | Indexed metadata search is established. A visible uncertainty ledger is an agent-driven interaction, but evidence that existing search cannot provide it is lacking. Index-based search likely wins on repeated queries. |
| 3 Role-aware duplicate review | [fdupes](https://manpages.debian.org/bullseye/fdupes/fdupes.1.en.html), [Synology Storage Analyzer](https://www.synology.com/en-au/dsm/7.2/software_spec/storage_analyzer), [Immich duplicate utility](https://docs.immich.app/features/duplicates-utility/) | Exact duplicates and photo similarity are already available; SHA equality is not semantic similarity or permission to delete. User-supplied roles could improve review but this is untested. |
| 4 Migration collision preflight | [rclone check](https://rclone.org/commands/rclone_check/), [rsync](https://rsync.samba.org/ftp/rsync/rsync.1) | Established transfer/reconciliation workflows handle many related issues; a rules-explicit cross-platform name-collision plan is a possible packaged interaction, not demonstrated unique. |
| 5 Drift checkpoint | [restic](https://restic.readthedocs.io/en/stable/040_backup.html), [ZFS snapshots](https://cdn.truenas.com/docs/references/zfsprimer/), [Nextcloud versions](https://docs.nextcloud.com/server/stable/user_manual/en/files/version_control.html) | Existing backup/version systems capture changes with substantially stronger integration than a user-managed text manifest. The useful increment is explicit uncertainty about unverified bytes, but no proven advantage. |
| 6 No-op organization plan | General file manager previews; [Syncthing conflict behavior](https://docs.syncthing.net/users/syncing.html) | Policy-based filtering and preview are ordinary; user-specific natural-language policy plus no-op accounting might improve review, but not demonstrated. |
| 7 Verification ledger | [rsync](https://rsync.samba.org/ftp/rsync/rsync.1), [restic](https://restic.readthedocs.io/en/stable/100_references.html) | Strong logging and verification already exist. Explicit expert-pending and unverified state could improve AI agent reliability; no supported durable journal or atomic rollback is documented. |
| 8 Read-budget frontier | [DuckDB selective Parquet scans](https://www.duckdb.org/docs/current/data/parquet/tips), [rclone check](https://rclone.org/commands/rclone_check/) | Resource-aware selective computation is old. An interactive, user-prioritized assurance frontier over folder comparison could be a new combination; no close exact match was established in the reviewed sources, which does not prove one is absent. A hard byte limit currently lacks a documented UGREEN enforcement primitive. |

## Nearby ecosystem

[Paperless-ngx duplicate handling](https://docs.paperless-ngx.com/faq/) and [Immich mobile backup](https://docs.immich.app/features/mobile-backup/) use existing document/photo management workflows; they are not general filesystem reconciliation engines. [TrueNAS](https://cdn.truenas.com/docs/references/zfsprimer/) and Synology systems provide filesystem-integrated snapshots or storage management; UGREEN Skill instructions should not imply comparable native change tracking. Unraid product behavior was not independently verified for this shortlist; no claim is made about it. More competitor research is necessary before any broad originality claim.

Mechanism classification: #1, #2 and #3 are primarily known methods with potential AI-guided interaction and optimization; #4 and #6 primarily familiar preflight procedures; #5 is a weak substitute for native incremental systems; #7 is safety packaging with a potential reliability benefit; #8 is a possible interaction/combination, unproven and blocked by runtime requirements. None establishes a new underlying algorithm.
