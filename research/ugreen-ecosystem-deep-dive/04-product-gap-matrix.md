# Product-gap matrix — ten evidence-grounded frictions, not ten Skills

Each “potential contribution” is a hypothesis or human-assisted fragment; it is **not** an invented native API, validated product gap, or candidate that passed the later gate. Evidence/limitations and model applicability in [FAQ analysis](02-faq-deep-analysis.md) and [dependencies](03-application-dependencies.md). [FAQ](https://community.ugreen.com/nas/pagesD/circle/post?id=1210), [UGREEN apps article](https://ai.ugreen.com/blogs/knowledge/top-7-nas-applications-for-performance), and source-specific links provide the real workflows.

| User goal | UGOS / third-party solution | Remaining friction and evidence needed | Possible AI contribution / availability | Improvement and novelty risk |
|---|---|---|---|---|
| Verify backup really restores | Sync & Backup restore; Kopia/restic checks. | Separate restore, app-open check, dates/metadata and independently protected keys; a green task is insufficient. | Read/hash an already-restored authorized sample if present. **Partial only**; backup job/restore/access to keys unavailable. | Could disclose what was compared; generic hashes and our prior benchmark overlap, cannot certify restore. |
| Restore one lost file without overwrite | Backup/Restore; File Version Explorer and snapshots where enabled. | User report of folder-level restore in one configuration; version/target disputed. | Find an accessible surviving copy; `cpmv` only if approval and safe semantics established. | Project Rescue and generic file assistant already tested; exact real backend behavior unresolved. |
| Rebuild an application after loss | Docker Project + application-specific guides; existing backup tools and xsm-bf. | Compose, volume data, DB consistency, keys, image/version, ports and runtime dependencies. | Inspect sanitized user-supplied config/manifest; compare authorized already-visible paths. | Could surface an obvious missing declared path; live volume, actual backup coverage and test restore inaccessible; generic report and Rebuild Kit overlap. |
| Identify which apps a folder change may affect | Files/organizer plus Docker/mount UIs. | Running mounts and hidden references may differ from saved config. | Compare a specific sanitized declaration with a selected path; qualify scope. | Impact Rehearsal overlap; cannot infer complete dependencies or safely automate. |
| Confirm phone photos reached NAS | Photos + mobile app; Immich/PhotoSync. | Phone upload state and full-resolution iCloud source; representative community reports. | Inspect returned NAS items only. | Can't establish what is missing on an inaccessible phone or fix uploader; no meaningful end-to-end Skill. |
| Fix an unreadable share | UGOS User/Group + Shared Folder permissions. | Effective ACL/group/SMB/mount/storage status. | Ask user for non-sensitive observations; no live ACL API. | Decision tree already in FAQ; generic assistant can restate it. |
| Find why HDD won't sleep | Storage/app/Task Manager and manual isolation. | Actual per-process I/O, scheduled jobs, controller activity. | Read explicitly exported safe notes if any. | No telemetry/monitor; scanning might itself wake disks. |
| Locate growing Docker storage | Docker usage/log/volume UI and app administration. | Layers, named volumes, internal data vs bind mounts; danger of deleting active state. | Inspect user-selected visible files; cannot measure daemon-level attribution. | False completeness and unsafe cleanup risk; no supported pruning. |
| Correct media misidentification | Theater manual metadata correction; Plex/Jellyfin and published media organizer. | Filename, media item ID and external match; current library index. | Inspect returned filenames + real media expert results if mapping available. | Native manual correction and GitHub organizer overlap; no assured metadata write. |
| Ensure recording, not just live feed | Surveillance Center mode and actual recordings. | No events may be normal for event-only; need mode, recording schedule, coverage and clip results. | Retrieve returned actual event evidence with `security-monitor-agent`. | Can't observe full recording settings or infer outage from zero events. |

No frequency labels here are market estimates. Multiple photo/background and backup discussions indicate a recurring *topic*; exact prevalence and current bug status are unmeasured. A productive unanswered question is whether an actual expert can return a complete authorized sample path, status and content hash; even if yes, this only supports a bounded fragment, not an installed product advantage.
