# Actual UGREEN NAS ecosystem: workflows, data and boundaries

Research date **27 October 2026** local. This is a research map, not a hardware test. Primary references: [UGREEN NAS applications article](https://ai.ugreen.com/blogs/knowledge/top-7-nas-applications-for-performance) (complete article, including storage, third-party apps, resource planning, HTTPS and ten pre-deployment checks); [October 23 FAQ](https://community.ugreen.com/nas/pagesD/circle/post?id=1210), rendered and read in Chromium; [iDX6011 Pro specification](https://ai.ugreen.com/products/ugreen-idx6011-pro-ai-nas); [iDX AI file organization](https://support.ugnas.com/detail/article/en-US/877); [Indexing Service](https://support.ugnas.com/detail/article/en-US/108); [File Version Explorer](https://support.ugnas.com/detail/article/en-US/316); [Sync & Backup](https://support.ugnas.com/detail/article/en-US/401); [storage protection comparison](https://support.ugnas.com/detail/article/en-US/651). Model/firmware applicability belongs to each source; do not assume the finalist's particular installed version or configured services.

The apps article distinguishes the device/client app, NAS App Center apps, containers, VMs and download packages. It states DH2300 lacks Docker/VM Manager; DH4300 Plus supports compatible ARM64 containers but not VM Manager; current DXP supports x86-64 containers/VMs subject to resources. Its comparison omits iDX, so **do not infer its support from the DXP row**. The [iDX6011 Pro product page](https://ai.ugreen.com/products/ugreen-idx6011-pro-ai-nas) advertises UGOS Pro and Docker/VM; installed version and feature enablement on the contest device are unknown. Hardware support ≠ Uliya capability.

| Usage category and goals | Native / other apps; persistent data and illustrative scale | Failure and existing workflow | Documented Skill surface versus missing system control |
|---|---|---|---|
| 1. Personal/shared files: multiple users store and retrieve material | Files, Universal Search, shared/personal folders. Hundreds to millions of files, variable; examples, not source statistics. | Duplicates, misplaced data, conflicts and accidental deletions. Files supports viewing and organization; iDX AI organizer creates an adjustable preview and collision policy. | `file-agent` lists/finds/reads/scoped hashes and requests approved moves; no guarantee complete inventory, atomic operation, ACL inspection or native organizer parity. |
| 2. Multi-device synchronization | Sync & Backup, UGREEN clients, Cloud Drives; Syncthing/Nextcloud possible separate apps; current file state and sync config/retention. | Two-way sync may propagate a deletion or corruption; the phone may have only an optimized copy. Use direction and version settings; sync alone not an independent backup. | Accessible NAS files can be examined; no documented client-side upload state, phone photo library, source-device access or sync-job API. |
| 3. Backup and recovery | Sync & Backup, File Version Explorer, Btrfs snapshots; restic, Kopia, Duplicati. Protected file/metadata state, backup repository, retention rules and separate keys. | Job success can differ from recoverability. Native backup/restore, Explorer and snapshots solve different problems; periodic sample restore in isolated location is recommended. | Read/hash a user-restored accessible sample if returned; cannot invoke restore, decrypt repository, inspect jobs, enforce application-consistent backup or certify recovery. |
| 4. Photos/videos | Photos, mobile app, photo expert; Immich. Original files, metadata, catalog and app configuration; 10k+ photos is an illustrative workload, not prevalence. | iOS background and source-quality restrictions; missing phone copy cannot be discovered by searching only NAS. Photos is not independent backup. | `photo-agent` search/detail where supported; no guaranteed direct original bytes, phone-state access, full library coverage or independent cloud-original validation. |
| 5. Media libraries | Theater; Plex, Jellyfin, music apps. Source media, naming, libraries, watch-state DB, thumbnails and config. | Incorrect scraper title/year; library catalog/index may not reflect file changes; native Theater permits correction. Plex/Jellyfin expand client features but need service administration. | `media-agent` catalog/search and playback for supported contracts; filesystem observation does not prove app-library visibility, database health or playback availability. |
| 6. Network file access | UGREENlink, SMB, WebDAV; Tailscale/WireGuard as applicable. ACLs, credentials and routes are sensitive; no need to ingest secrets. | Remote/browser/SMB/VPN failures can occur in separate layers. FAQ recommends isolated checks rather than exposing SMB publicly. | User-provided, sanitized observations can be summarized; documented file tools do not prove ACL, VPN, ports, network route or SMB reachability. |
| 7. Application and container hosting | Docker Project/Container, some model-dependent VMs; Nextcloud, Home Assistant, Vaultwarden, DNS and backup tools. Compose configs, bind mounts, named volumes, databases, secrets and app versions. | Container image may be disposable; its state/dependencies may not be. Relative path resolution and live volumes can differ from source YAML; updates can require database/version-aware restore. | `cat`/document tools can examine explicitly authorized **sanitized** user-supplied files; no documented Docker daemon/API, volume enumeration, live environment, container restart, SQL dump or service-health control. |
| 8. Indexing and organization | Indexing Service, iDX Files AI organizer; metadata and system thumbnails. | Initial indexing consumes time/resources; omitted scope or disabled index can make files unsearchable. UI supports thumbnail settings/regeneration. iDX organizer supports up to 2,000 at a time per cited guide. | `find`/`ls` exist, but no documented access to index status, index records, scheduling or optimizer. Do not promise full 100k-file coverage. |
| 9. Collaboration and permissions | User/Group, Shared Folders, UGREENlink, expiring links/collection links. | FAQ prioritizes Denied > Read Only > Read/Write > Not set; group restrictions can override a direct grant. Different boundaries can warrant different shares. | `stat` is not a documented effective-access/ACL diagnostic. User-supplied policy and explicit access to safe evidence only; no permission repair. |
| 10. Maintenance/reliability | Storage Manager, SMART, snapshots, task manager, monitoring apps; logs and historical state. | SMART quick test is not complete drive clearance; RAID consistency is not backup or SMART. Local Uptime Kuma cannot report its own host/power outage. | Catalog has camera-event tools, **not** SMART/pool metrics, system logs, Docker usage, snapshot lifecycle or external health monitoring. |
