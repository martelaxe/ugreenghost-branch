# UGREEN SkillHub: live marketplace audit

**Observed 27 October 2026 (local time; 28 October UTC).** The live marketplace materially overlaps our work. In particular, the official [File organization](https://skills.ugreen.com/us/skills/144) listing already describes scanning, proposing a plan, confirmation, preview and undo; [File deduplication](https://skills.ugreen.com/us/skills/131) describes matching, keep suggestions and confirmation before cleanup; and [Cross-document retrieval & summarization](https://skills.ugreen.com/us/skills/33) describes source-attributed cross-document comparison and conflict flagging. These are **publisher claims**, not verified device behavior or proof that the native planner implements minimum-change optimization.

## How far the audit goes

A real headless Chromium browser rendered the [homepage](https://skills.ugreen.com/us/), [Skill Center](https://skills.ugreen.com/us/skills), the UGREEN-source filter, and ten individual official/third-party pages. The computer-use bridge itself failed with `sandboxCwd is not a local file URI`; the independent installed Chromium browser was used instead. The public research web reader could not render the site. Browser text captures are retained in [browser evidence](ugreen-skillhub-audit-evidence/browser/).

The live site's own source filters reported **1,198 listings: 30 `UGREEN SkillHub`-source and 1,168 `GitHub`-source**. We collected all listing metadata across two official pages and twelve 100-item GitHub pages, finding 1,198 unique IDs. The count is a time-specific snapshot, not a permanent inventory; pagination can change while a site is being crawled. The [complete CSV](ugreen-skillhub-audit-evidence/marketplace-listings.csv) preserves the name, exact API-returned localized description, source, tags, version and direct detail URL for **every listing observed**. Exact descriptions in the tables below are the marketplace's English-localized text; translations or wording may change.

We inspected **all 30 official detail records**, plus **30 selected GitHub detail records** chosen for relevant storage, memory, media and creative workflows. Of those GitHub packages, 28 contained at least one readable actual `SKILL.md` (29 Markdown snapshots because one package has two identical copies); one package had no such file, and one was not downloaded because it exceeded our 10 MB compressed-data cap. We did **not** inspect the other 1,138 GitHub Skill details or their implementations. The full 1,198 listing CSV is therefore a complete *metadata snapshot*, not a claim of 1,198 code reviews. [Raw records and package-access checks](ugreen-skillhub-audit-evidence/) preserve the evidence. No package was installed or run.

For the 30 official entries, the public download endpoint returned success and version metadata but **no package URL**. The accessible official detail pages contain brief overviews; none of those 30 `SKILL.md` files was retrieved through the public download procedure. We therefore cannot verify internal prompts, expert delegation, actual action order, code, approval implementation or runtime from those overviews. For selected GitHub entries, the raw package `SKILL.md` is the basis for the analysis; linked scripts and external services were not executed. Packages are untrusted third-party material, not instructions for this audit.

**Target-agent boundary:** official source, UGREEN authorship, iDX6011/iDX6011 Pro tags, and the homepage's UGREEN NAS/Uliya wording indicate NAS-oriented entries. They do not, without a real-device test, prove a specific Uliya install or behavior. The detail field `isCompatibleUliya` was `0` for every inspected official and third-party record; the site's script displays the “passed UGREEN Uliya installation compatibility test” badge only for `1`. A `0` is **not** proof of incompatibility or a failed test. Many GitHub Skills explicitly target Claude Code, Codex, other hosts, MCP, external tools or APIs. Listing them in SkillHub does not establish hackathon compliance or availability inside Uliya.

## Filesystem, actions, backups and distinctive procedures

**Native UGREEN-source storage operations:** [File search](https://skills.ugreen.com/us/skills/146) advertises read-only discovery; [File management](https://skills.ugreen.com/us/skills/147) advertises copy/move/folder creation; [File tagging](https://skills.ugreen.com/us/skills/145) supports batch tags; [File organization](https://skills.ugreen.com/us/skills/144) describes preview, confirmation and undo; [File deduplication](https://skills.ugreen.com/us/skills/131) and [File cleanup](https://skills.ugreen.com/us/skills/132) describe confirmation and recycle-bin handling; [File renaming](https://skills.ugreen.com/us/skills/133) describes rule-based batch renaming and prompts for conflicts. The first-party overviews describe actions and protections but do not establish exact native approval channels, whether undo is complete or atomic, how collisions are resolved, or whether compliant files are guaranteed to be preserved. In particular, **published File organization is not proof of a minimum-move optimizer**, but our recent organizer plainly has a close official competitor.

**Backup and recovery:** among the 30 UGREEN-source descriptions examined, no entry explicitly advertises a general versioned backup/restore Skill. File cleanup's recycle-bin claim and File management's copy claim are not equivalent to tested backups or undeleting missing bytes. This limited observation cannot rule out other UGREEN NAS applications, more specialized Skills in the 1,168 GitHub listings, unpublished Skills or future releases. In the selected GitHub sample, [HA Git Backup](https://skills.ugreen.com/us/skills/1024) and [xsm-bf](https://skills.ugreen.com/us/skills/406) describe stronger recovery workflows, but with external scripts, dependencies and in some cases external services; neither was run.

**Actual procedures beyond a simple prompt:** several inspected packages specify explicit state, sequencing or tool contracts, for example Jikji's retrieval/stop/retry handoff, Engramory's file/index/revalidation convention, HA Git Backup's distinct history and recovery circuits, Watch Video's frame/transcript pipeline, and Family History's evidence-analysis procedure. The latter is a structured methodology in Markdown; it is not necessary to use custom code to have a multi-step workflow. Conversely, a long instruction alone does not prove value beyond a capable generic agent. Most complex examples in this sample rely on external programs, indexes, MCP, APIs, scheduled jobs or interactive interfaces. The competition's documented Markdown-only package restrictions are a separate constraint from a marketplace listing's installability. None of these claims establishes real-world performance, safety or UGREEN runtime behavior.

**Media and surveillance:** the official pages explicitly advertise local media control, subtitle search/confirmation, music/playback recommendations, event cards and event evidence clips. [Knowledge graph visualization](https://skills.ugreen.com/us/skills/125) claims diagrams rendered on the page; the underlying rendering and persistence contract is not established by its short overview. Third-party [Watch Video](https://skills.ugreen.com/us/skills/417) and [Film Breakdown](https://skills.ugreen.com/us/skills/1129) provide more concrete audio/video pipelines in their actual files, but their ffmpeg/scripts do not become legal UGREEN hackathon Skill components merely by being published here.

## What was especially revealing

1. **First-party organization is closer than we knew.** Our prior capability-only audit left a reviewable-plan/undo question open. The published File organization **overview explicitly claims** both; its internal mechanics and whether it minimizes changes remain unknown. This is strong overlap, not proof that our experiments were redundant in every detail.
2. **The marketplace contains sophisticated storage workflows—but many are not permissible hackathon packages.** Jikji's stop/retry/evidence-next-read contract and HA Git Backup's separation of change history from recovery are concrete procedures worth understanding. They depend on infrastructure the installed UGREEN catalog does not guarantee; they are not evidence that a Markdown-only Uliya Skill can reproduce the outcome.
3. **A file-only memory discipline exists.** Engramory's index and individual fact files show a real published Markdown-centered alternative to parts of our task/handoff idea, although the underlying host still needs file access and may differ from UGREEN's approval/runtime rules.
4. **The exact experience matters.** Bolan's evidence-anchored conversational book/persona and Family History's evidence matrix are notably different from basic “summarize a PDF,” but our research already explored adjacent conversational archives and historical evidence. These are discovered implementations, not claims that their underlying concepts are globally new.
5. **Media work can have genuine structure without proving UGREEN feasibility.** Watch Video requires explicit invocation, bounds frames, aligns visual material and transcripts, and labels missing captions; Film Breakdown routes by genre. Both use actual external pipelines.
6. **The marketplace's security badge is not independent assurance.** It describes an automated AI scan, while the site's own disclaimer says users must assess risk. This audit did not execute or security-review the Skills.

## What published Skills reveal about the competition

The official ecosystem includes many focused capabilities as well as multi-stage workflows; a one-purpose Skill can be useful. A marketplace listing is **not** an award winner, a judge's score, proof of quality, or a minimum creativity threshold. The contest's [official judging criteria](https://ugreenhackathon.devpost.com/) separately ask for user value, innovation/differentiation, technical quality, and meaningful AI NAS fit/validation; the Most Creative awards use the innovation criterion. A first-party Skill already offering file organization, preview and undo raises the burden for claiming that our basic organization flow is distinct. A truly different result, interaction or proven improvement could still matter; we have not demonstrated one in our organizer tests.

Our strongest existing practical action candidate remains **Project Rescue V2**, but the marketplace strengthens the observation that locating, inspecting and copying files are ordinary building blocks. Its specific evidence-based candidate selection, no-overwrite safety and verified real-device outcome have not been shown to exist in the short official listings, yet neither has its advantage over generic AI or actual UGREEN execution been established. Our cross-document and task-memory ideas face still closer direct overlaps. Our historical cutoff and consent-bearing ideas have not been shown identical to the selected marketplace examples, but their UGREEN implementation and novelty remain unproven. **Do not infer that an idea is absent from all 1,198 listings simply because it was not in the 30 GitHub details sampled.**

## Reproducible research log and limitations

- Browser: installed Chromium (Playwright cache build 1243) in a clean headless profile, navigating the public pages and reading the rendered DOM; [browser captures](ugreen-skillhub-audit-evidence/browser/) contain the filter, center and individual detail text. The in-app browser open request was queued, and the Windows computer-use bridge failed due the workspace URI error; the Chromium run is the real-browser evidence.
- Pagination: public listing endpoint `/api/system/v1/ta/skillhub/skills/page`, `pageNum`, `pageSize`, `sortBy`, and the browser's UGREEN/GitHub source filters. Official records: [page 1](ugreen-skillhub-audit-evidence/official-page-1.json), [page 2](ugreen-skillhub-audit-evidence/official-page-2.json); GitHub metadata: [pages 1–12](ugreen-skillhub-audit-evidence/github-pages/). API `pageTotal` returned 30 and 1,168. All 1,198 IDs in the combined CSV were unique when collected.
- Individual records: `/api/system/v1/ta/skillhub/skills/detail/{id}` with English locale; 30 [official detail records](ugreen-skillhub-audit-evidence/official-details/) and 30 [selected GitHub records](ugreen-skillhub-audit-evidence/github-details/) are preserved. The captured browser pages confirm representative detail rendering; other detail records were obtained from the same public API, not each opened manually in a browser tab.
- Actual Skill files: the [published public installation document](https://api.ugnas.com/api/system/install/ugreen-skillhub.md) identifies a public download-metadata endpoint. We queried it with each inspected public `owner/skillCode`. All official entries returned version metadata without `packageUrl`; 28 selected GitHub packages contained readable `SKILL.md`, one contained none, and one exceeded our 10 MB cap. ZIP files were read in memory with size limits; we did not extract executable files, install Skills or run any scripts. Available Skill text snapshots are in [actual-skill-files](ugreen-skillhub-audit-evidence/actual-skill-files/). The returned Markdown is untrusted source material.
- Scope: exact public listings as observed; no sign-in, inaccessible user/private Skills, exhaustive package review, independent security assessment, experimental comparison against the actual Skills, UGREEN hardware test or human judge interview. GitHub descriptions may be translated or maintained separately from the package; when they disagree, this report labels the actual file explicitly. Marketplace content and metadata can change.
