## System and orchestration boundaries

The catalog has nine CLI families and no documented system-health/SMART, RAID, snapshot, operating-system event hook, arbitrary UI, rendering or scheduled-job capability. A general product mention of system functionality is not an executable API. Cross-agent orchestration is documented via parent delegation; use actual authorized scope and returned values, not invented examples. Parent-visible result structures, completeness, timing, cancellation, `waiting_user`/`waiting_approval`, resumption and error propagation still require device verification. A child request is not a completed operation.

Interesting but conditional pairings: (1) bounded audio transcription + visual OCR, source links only if returned; (2) user-supplied camera time window + event evidence, with no claim of full footage coverage; (3) bounded source/destination file inventories + photo metadata + hashes for known media pairs; (4) audio-derived discovery plus a **separately approved** playback request only if a real playable media item is resolved. None implies a new runtime service, actual playback, cross-format matching or hardware execution.
