# Frontier research: mechanisms rather than names

Cutoff 2026-10-27. Dates below are publication/submission dates where available. Research claims are the authors' results, not replications; capability implications are our interpretation. Project-local prior coverage was checked in [coverage audit](coverage-audit.md).

| Source | Actual mechanism and evidence | What it changes here / limits |
|---|---|---|
| [SKILL.state](https://arxiv.org/abs/2608.26263), 2026-08-26, revised 2026-09-02 | Immutable skill plus explicit mutable state and latest observation; discards intervening reasoning after a validated state update. Authors report accuracy and token improvement across their tested settings. | Task Capsule already studied handoff; **validated state transition replacing transcript replay** is a more specific runtime mechanism we had not established. Needs runtime state validation and storage, not just Markdown. |
| [Graph-of-Skills](https://arxiv.org/abs/2604.05333), 2026-04-07, revised 2026-09-11 | Offline dependency graph; hybrid retrieval, reverse-aware personalized PageRank and budgeted hydration. One reported GPT-5.2 Codex/SkillsBench result: +7 absolute reward points against full loading, 56.7% fewer tokens. | **Retrieve prerequisite skills as a bundle** rather than the nearest skill alone. Performance is benchmark-specific; graph construction and routing are not provided by UGREEN's catalog. |
| [SE-GoS](https://arxiv.org/abs/2609.08228), 2026-09-08, revised 2026-10-01 | Updates graph topology, edge weights and node descriptions using execution traces while keeping skills, model and retrieval pipeline fixed. One evolution round improved reported SkillsBench average reward 52.4% to 59.4%; repeated evolution did not help. | **Correct a retrieval index using observed co-use and counterevidence**, rather than rewrite the skill after each result. Needs logged traces, offline updating and evaluation. |
| [Skill-Pro](https://arxiv.org/abs/2602.01869), 2026-02-02, revised 2026-05-28 | Skill initiation, execution and termination; semantic candidate generation and a non-parametric PPO gate select and maintain reusable procedures without changing model parameters. | **Gate learned procedural updates against execution outcomes**. Our skill quarantine and SkillCAT were already related; this specific scoring and gating method is distinct, not demonstrated under UGREEN. |
| [SkillAlign](https://arxiv.org/abs/2609.07255), 2026-09-07 | Candidate skills become multi-view procedural cards; full instructions, hints, compressed summaries, workflow or no exposure compared with the same task and candidate set. Authors report meaningful task-success and context-cost effects. | **Change the interface through which an identical skill is exposed**, a different variable from selecting or rewriting skills. Our prior generic-vs-specialized tests did not isolate exposure interface. Requires controlled harness to establish benefit. |
| [HASP](https://arxiv.org/abs/2605.17734), 2026-05-18, revised 2026-09-28 | Executable functions inspect failure-prone agent states and intervene in the next action or context. Authors report gains on selected web, math and coding tests. | **Runtime interception**, stronger than advisory Markdown; no published UGREEN hook for arbitrary agent-loop code. Prior safety skills and YoloFS already overlap the goal. |
| [LESS, FAST 2026](https://www.usenix.org/conference/fast26/presentation/cheng), 2026-02 | Builds layered extended sub-stripes over Reed–Solomon codes to trade accessed bytes against noncontiguous seeks during repair; implemented on HDFS and evaluated against other erasure codes. | **Design redundancy around recovery I/O rather than only storage size**. This is a distributed storage encoding change, not an AI feature or something a Skill can add to existing NAS files. |
| [Redundancy Does Not Imply Fault Tolerance](https://www.usenix.org/conference/fast17/technical-sessions/presentation/ganesan), FAST 2017 | Studies fault-handling failures in distributed storage systems. | **A redundant copy is not an end-to-end recovery guarantee**. No claim a user has a working restore because a copy, parity or snapshot is present. |
| [EM²Mem](https://arxiv.org/abs/2609.00551), 2026-09-01 | Constructs event-anchored cells binding multimodal records, temporal context, relations, semantic facts and provenance for long-video QA. Authors report improvements of 2.0–3.7 points across three benchmarks and better strict event recall. | **Align evidence at ingestion before retrieval**, rather than asking a model to reconstruct alignment from fragments. No documented UGREEN event-memory index or video decoder; wrong alignment can mislead. |
| [SyncSink](https://github.com/JorenSix/SyncSink), project citing 2015 research | Audio-to-audio alignment synchronizes recordings from independently operated cameras. | **Use shared sound to establish relative event time despite wrong camera clocks**. Existing research and editing software already do it; needs audio signal processing, not documented UGREEN. |
| [OHMS](https://journal.code4lib.org/articles/10643), 2015; [Oral-History.Digital](https://www.oral-history.digital/en/hilfe-neu/hilfe-erschliessen/ohd_tutorial_6/index.html), date not shown | Oral-history systems connect transcript or index to time positions in source recordings; the latter notes timecodes are useful, not mandatory. | **An evidence pointer becomes navigation into original audio**, not merely a paragraph summary. UGREEN transcript `segments` exist in catalog, but timestamps and playable deep links are not guaranteed. |
| [Edge-agent survey](https://ijcai.org/proceedings/2026/858), IJCAI 2026 | Reviews privacy, heterogeneous devices, autonomy and resource/context limits of LLM agents on edge hardware. | Local ownership can reduce transfers but does not automatically guarantee offline inference, confidentiality, model quality or isolation. |
| [Frigate recording](https://docs.frigate.video/configuration/record/) and [history](https://docs.frigate.video/usage/history/), documentation, date not shown | Event results, retained recording segments and configured pre/post capture are different things; absent footage has several possible causes. | **Treat event detection and recording coverage as separate evidence domains**. A missing event cannot establish no event occurred or footage never existed. |

At least five distinct mechanisms above are new to our reviewed project: state transitions, dependency-aware skill hydration, exposure-interface control, programmatic intervention, waveform synchronization, event-aligned multimodal cells and repair-aware erasure coding. Some have precedents in earlier work; the precise mechanism and practical differentiator are what is new to this review. An audio transcript plus image is not proof of temporal co-occurrence.
