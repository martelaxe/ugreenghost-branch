# Three candidate experiences

## 1. Readiness Delta — provisional leader

- **Promise/user/request:** an organizer says “Are these selected materials ready for my stated use, and what changed since my previous review?” It checks explicit purpose-specific requirements against authorized stored evidence.
- **Inputs/procedure:** current requirements, target files, and an optional explicitly provided earlier review; identify requirements, locate support and contradictions, mark PASS/FAIL/UNKNOWN/N/A, compare like-for-like only when a previous review is actually supplied.
- **Result/action:** concise evidence-based review and one safe next step; optional independently verified save only after user and platform approval. No OS-enforced release block or automatic history.
- **Tool mapping:** file-agent `ug-filesystem` reads/discovery; document-agent `ug-document` extraction/reconciliation; optional knowledge-agent `collect-evidence` and `save-text`.
- **Safeguard:** no PASS without positive evidence, incomplete access stays UNKNOWN, no unverified legal certainty or save.
- **Competitor:** ClaimReady and Adobe DAM already do important parts; Nextcloud can analyze files. **90 seconds:** existing set passes; edit one permission in a controlled fixture, rerun, show requirement and source become FAIL, while unrelated edits should not flip it. **Failure:** stale or absent source is presented as proof of readiness. **Ordinary-AI objection:** most of this is prompt-guided source comparison and a table.

## 2. Evidence Stress Test

A freelancer asks “What evidence could overturn this payment claim?” over invoices and contracts. Investigate counterevidence and narrow claims; output a citeable challenge and questions. File/document/knowledge agents read scoped files; optional approved text save. No assumption that a search miss proves a claim. Competitor: legal due diligence and document review products; demo one overlooked revision. Failure: confident refutation based on unrelated or uncited evidence. It is generic adversarial document QA, with no demonstrated cross-time experience.

## 3. Recoverability Rehearsal

A creator asks “Can another person recreate this project from this selected folder?” over manifests, assets and documentation. Attempt a *read-only* component-and-dependency check, show missing evidence and a small reconstruction plan; do not claim a project is operational. File/document agents; optional approved save. Competitor: Adobe link media and archival workflows. Demo a documented asset version mismatch. Failure: treating a missing reference as confirmed nonexistent or asserting an app will run. It overlaps previous Impact Rehearsal and generic file inspection, and cannot directly launch apps.

Selection is provisional and not based on a claim of global originality. The more general Readiness Delta is retained for the falsifiable before/after test; it is rejected as a differentiation claim if generic G produces equivalent behavior and it remains only a contradiction report.
