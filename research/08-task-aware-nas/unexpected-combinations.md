# Eight combinations that change an outcome

These are proposed experiences, not verified inventions. Each assumes user-authorized sources; none requires automatic file movement, a background service, an interactive graph or a real UGREEN device. Source-backed needs: [new user evidence](new-user-evidence.md); close competitors: [reality check](competitor-reality-check.md).

1. **Creative reuse + rights + unmet brief → Creative Salvage.** Show a new pitch drawn from abandoned notes and a rights restriction that changes which route is available. Creativity alone can suggest unusable work; a rights list alone doesn't create a project. Combined outcome: a concrete, human-reviewable pitch with a hold on the restricted asset. Test whether creators value it more than generic Codex, and whether clauses really apply to an identified asset.
2. **Disputed versions + conditional output → Fork & Finish.** Instead of stopping at a conflict, show two labeled versions of a finished report and ask which to adopt. The comparison is useful because users can see the consequence of deciding; wrong arithmetic, unsupported assumptions or false finality defeat it. Generic Codex already did this in experiment 08.
3. **Explicit expectation + mistaken candidate → Exception or Error.** Compare a task's requirement against an exception note before searching for a missing document; produce “not expected”, “not found in reviewed scope” or “unknown”. This avoids wasting effort on a convincing but irrelevant match. Test with cancellation evidence and same-name wrong-year records.
4. **Recovery documentation + actual successor task → Rehearsed Recovery.** A real successor answers a concrete question using the selected instructions, revealing a gap the owner can repair. The additional value is a usability rehearsal, not an automated restore. Test with real users and do not certify backups.
5. **Photo metadata + conflicting family note → Time Travel Interview.** Turn disagreement into a question for a living relative, rather than a speculative fact. The outcome is a conversation anchored to two sources. MemoryJam already advertises close functionality; test what cross-source NAS integration adds.
6. **Source disagreement + investigation plan → What Would Change My Mind?** Show two interpretations and identify the exact existing or user-provided source that could discriminate between them. This is more useful than a contradiction list when it yields a feasible next investigation. Test whether the suggested source exists and would actually discriminate; label unknown otherwise.
7. **Project manifest + file inventory + path history → Lost Media Handoff.** Suggest candidate locations for missing project assets while preserving the original editor's authority to relink. The outcome is a human-readable relink plan, not media editing. Test against same-name, different-content files; proprietary project parsing is unverified.
8. **Expected inventory + archive gaps + permissions → Permission-Limited Completion.** Show what was answered, what may need an additional scope, and the precise authorization decision. It improves a finished partial report without assuming inaccessible items exist. Test a blocked folder and report unknown coverage, not an approval that has already happened.

## Rejected feature bundle

“Find duplicates, generate a family timeline, make a video, organize files and schedule reminders” adds operations without a single user outcome. Rendering, scheduling and automatic mutations are unsupported or unverified in the current Skill environment. It is not a candidate.
