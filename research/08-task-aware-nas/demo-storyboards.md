# Three proposed three-minute demonstrations

These are storyboards using fictional content. They are not UGREEN screenshots or claims of successful NAS operation. The only proposed interface is ordinary Skill conversation with returned source references. Every use of a photo can be replaced by an explicit, user-authored asset description until photo handoffs are verified.

## 1. Creative Salvage — the blocked asset changes the pitch

**User types:** “Using my authorized `old-projects` and `rights` folders, propose two feasible short-film pitches for a community exhibition; flag any asset I cannot safely reuse.”

**Inputs:** A fictional abandoned film note describing a silent street scene; an asset manifest identifying `scene-12`; an old location recording and a separate license note saying `scene-12` is restricted from public exhibition; a second independent written concept and its use terms. All are textual records for the minimal demo.

- **0:00–0:45:** User explains that a creative brief feels impossible with a small budget; selects folders. The Skill inventories the returned records within bounded scope.
- **0:45–1:45:** It proposes Pitch A using the street-scene premise but places a **hold** on the specifically identified restricted asset; shows the rights excerpt. It proposes Pitch B using a different, explicitly permitted written idea. A compelling idea may still be blocked.
- **1:45–3:00:** User chooses B or asks for permission review for A. Show a short cited pitch and unknowns. Any later stateful continuation is a planned device test; if unsupported, show both conditional outputs and ask the user to choose manually.

**Final outcome:** Two text pitches with original-source references, a cited restriction, coverage note and one safe next step. No automatic publishing or legal clearance. The exhibition cannot use a source without appropriate human review. **Judge memory question:** a promising film idea hits a visible constraint and the archive still offers a creative alternative; this is memorable only if the pitches themselves are genuinely good to a creator.

## 2. Knowledge Succession Rehearsal — a real person meets the missing step

**User types:** “Using this authorized handoff folder, give my colleague a short practice task for finding the spare filter and tell us what instructions are missing.”

**Inputs:** A maintenance note naming a blue box, a handoff note naming a contact, and an explicit checklist referencing a recovery note that was not among the retrieved files.

- **0:00–0:45:** Owner picks a small folder and introduces a novice; the task is understood immediately.
- **0:45–1:45:** The novice answers where the filter should be and whom to contact, with citations. The system notices the checklist references a recovery record absent from the bounded review.
- **1:45–3:00:** Show an exercise card with the next question for the owner. If the owner does not provide the record, the outcome remains unresolved.

**Final outcome:** A useful text practice card with exact evidence and a missing-input limitation; no claim that restoration or actual backup integrity was checked. **Judge memory question:** the second person's confusion makes an invisible handoff problem concrete; human participation and value remain untested.

## 3. Fork & Finish — show how an uncertain record changes the answer

**User types:** “Prepare my January–March invoice report from these authorized folders and show what changes if either February version applies.”

**Inputs:** A policy requiring revision approval, two February versions ($150 draft / $190 revision awaiting approval), and $100 January and $120 March invoices.

- **0:00–0:45:** User requests the report; the system locates the files.
- **0:45–1:45:** It displays both source-backed February versions and their statuses. Two totals are $370 and $410, explicitly conditional.
- **1:45–3:00:** It asks whether approval occurred and provides two copyable versions; without an answer it does not declare a final amount. If real multi-turn state works, a follow-up selects the corresponding draft; otherwise user makes the selection outside the Skill.

**Final outcome:** A useful conditional report and one clear decision, with no fabricated approval. **Judge memory question:** the decision makes a $40 difference; however, generic Codex already did this in our benchmark, so its distinctiveness must come from a demonstrated experience advantage, not the arithmetic.
