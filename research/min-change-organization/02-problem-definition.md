# Minimum-disruption organization problem

For user-authorized files F and explicit policy P, choose a safe proposed action for each known file: retain, relocate to an allowed destination, or defer with the missing decision. Lexicographic priority: (1) authorization and safety, (2) policy satisfaction where possible, (3) no unsupported classification or collision resolution, (4) minimum necessary moves, (5) lower work only after the first four. A zero-move plan that leaves known correctable violations unsatisfied fails; a bulk plan that moves compliant or ambiguous files fails.

A file can have multiple acceptable destinations. The evaluator treats existing compliant alternatives as valid and accepts any allowed unoccupied destination for a justified move. Unique destination assignments must not collide; where alternatives compete for fewer available slots, this experiment's explicit policy says defer every competitor rather than guess. No overwrite, deletion or rename is authorized. For eligible non-competing items, each currently noncompliant item needs at least one move, so the minimum is mechanically the number of independently eligible sources; the small collision subset is separately exhaustively checked. This proof depends on fixture policy, not arbitrary real-world organization. Missing metadata and inaccessible files stay unknown, not automatically noncompliant or compliant.

Count separately necessary moves, no-ops, collisions, ambiguous/prohibited actions, files left incorrectly classified, directory changes, content bytes, calls and model time. Duplicate bytes do not mean a file is safe to delete. A differently weighted move can be more harmful when references, active usage or sharing are known, but neither path proximity nor a guessed reference proves dependency. The fixture does not have trusted dependency data; no dependency-breakage metric is claimed. No exact overall optimum is implied for general multi-step moves, hard links, uncertain references, user preferences or concurrent mutations.

All experiment plans are proposals. User approval, platform approval, completion, and independent post-action checks are separate states. The local adapter exposes stronger listing/reading guarantees than the UGREEN catalog; `start` reports a plan, `run` summary reports aggregate outcomes, but reliable per-file no-op, collision or change verification is not promised. The tool study can measure local plan quality, not hardware execution cost or safety.
