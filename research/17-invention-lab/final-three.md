# Three distinct finalists

## W — Consent-Bearing Object: a file that can withdraw a future interaction

**Request:** “Let my sister ask the family album about this one story; later I want to stop future access without handing out the whole album.” The envisioned primitive is `grant(action, scope, recipient, expiry)` and `revoke(future use)`, enforced by a trusted data boundary, with evidence and output policy. The surprising behavior is that a digital object offers an operation instead of exposing its raw bytes. User value is multi-person memory sharing where wholesale export is excessive.

**Research:** YoloFS shows controls can move into the filesystem; Tahoe and clean-room systems already enforce aspects of access; MFM shows retained raw observations can support episodic recall. These existing systems make the components real but also seriously reduce the novelty claim. The possible invention is their household, purpose-specific, model-mediated interaction with revocable *future* access. It cannot erase previously disclosed outputs or prevent a user recording a screen. Purpose restrictions and AI output leakage are hard security problems. No current UGREEN Skill documentation guarantees an enforcement boundary. Our toy broker visibly failed when bypassed by a direct read. **Wildest and most conceptually interesting, not implementable by a Markdown-only Skill.**

## B — What-If Exhibit: a collection that recomposes around an omission

**Request:** “Keep our event's arrival, workshop and ending, but make a display that contains no red artwork. If a moment has no supported alternative, leave a gap.” The output is a three-slot exhibit, then an explicitly requested alternate view; an excluded source is replaced only by an eligible source for the same story beat. The surprise is that the artifact changes around a loss, without rewriting the underlying files, and shows a hole when it cannot honestly do so.

**Research:** combine versioned projections (lakeFS), explicit provenance (born-digital archive) and candidate admission with counterexamples (SkillCAT). Photo editors, smart albums, workflow systems and existing UGREEN contest photo Skills overlap strongly. The residual is the explicit user-authored story structure plus constrained recomposition and gap policy; there is no demonstrated novelty or unique intelligence, and generic Uliya may do it. Our local Python actually produced three SVG sheets from hand-labelled fixtures. A Markdown UGREEN fragment can propose a new selection on explicit request and optionally request an approved album; it cannot claim automatic reactive views, exact album order, safe publishing or actual runtime without a device. The demo is memorable only if the artifact visibly changes and the user can understand why.

## S — One-Bit Workshop: an archive asks the question that changes the next action

**Request:** “Help me make our event sign from what we have. Ask one question at a time.” The procedure extracts alternatives and their prerequisites, chooses one unresolved observation that separates viable next steps, waits, and routes the next action to a supported source. A real Codex run asked a four-option materials question; a fresh follow-up given a simulated answer suggested the handwritten route. This creates an interaction, not merely a summary. It is neither an implementation of formal expected-value optimization nor a measured improvement.

**Research and prior art:** Skill-Use highlights triggering and compliance, while REVOIR and active-inference papers already study the value of asking; generic AI tutoring and workflow trees are close. The NAS contribution would be access to owned procedural records, not a new dialogue algorithm. Document/file experts can plausibly supply facts, but current exact return shapes and interactive state are unverified. Safer and more Skill-native than W, but the smallest WOW and closest to generic assistants; no claim of novelty.
