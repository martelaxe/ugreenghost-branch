# Translation into the real UGREEN catalog

Checked 27 October 2026 using installed Uliya Skill Creation Tool 0.7.3, catalog 2.0.0, the expert-orchestration/safety/completion references, [rules](https://ugreenhackathon.devpost.com/rules) and [starter kit](https://ai.ugreen.com/pages/hackathon-starter-kit). The parent delegates to each CLI's sole registered expert; child chooses actions. No parent `cli.invoke` or local code inside the exploratory Skill.

| Step | Documented owner/actions | Inputs and limitations |
|---|---|---|
| Find source notes and media paths | `file-agent` / `ug-filesystem`: `find`, `ls`, `cat` | `find` and `ls` require `path`; limits and max depth available. Actual coverage, hidden files, permission behavior and resolved path provenance remain unknown. |
| Extract beat/source constraints | `document-agent` / `ug-document`: `extract`, `qa` | `query` required, optional `file`, `max-files`, `body-cap`. It may identify text in documents; no guaranteed complete coverage or parent-visible exact excerpt. |
| Inspect actual photo candidates | `photo-agent` / `ug-photo`: `search-picture`, `meta`, `vision-vlm` | Documented search/inspection and vision operations, but actual item IDs, model availability, visual accuracy, runtime data handling and privacy are unknown. A vision guess is not consent or proof an image satisfies a sensitive constraint. |
| Optional new album | `photo-agent` / `ug-photo:create-album` | Catalog lists optional `album-name`, `add-item`, `sub-type`, `query`; state-change with workflow approval. `add-item` encoding and returned real UUID/parent propagation are unverified; do not guess. Explicit owner approval and platform workflow approval required. No evidence of guaranteed album order, visibility, atomicity, rollback or reactive rebuilding. |
| Check resulting album | `photo-agent` / `ug-photo:album-detail` | `album-uuid` and `get-type` supported; result requires real album identity. Actual membership visibility/propagation unknown; an absent return means unverified. |
| Save a textual exhibit plan | `knowledge-agent` / `ug-knowledge:save-text` | Optional documented workflow-approved write with `path`, `content` or `content-ref`, `filename-hint`. Not needed for this minimal idea; exact write safety and returned path are unknown. No need to add a fourth agent just for novelty. |

**What the Skill adds:** a specified slot/alternative/gap policy, on-demand recomposition under a user-specified exclusion, and a careful separation of preview, permission and actual album state. A generic Uliya agent might do all of this when asked; we did not compare them. Our actual local SVG renderer is custom research code and cannot be embedded in the Skill. The Skill does not dynamically re-render an exhibit, preserve album ordering, infer image rights, guarantee privacy, or update an existing shared album. No assumption of a callable or installed vector renderer.
