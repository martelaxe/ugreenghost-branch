# Actual affordances and uncomfortable unknowns

DOCUMENTED refers to installed catalog/standard, not device execution; documented field descriptions are **summaries**, not guaranteed complete schemas. The complete [per-action catalog](02-operation-catalog.md) records every effect and approval. All source access requires an authorized user scope even if the catalog says approval `none`.

| Question | Classification | Evidence and precise limit |
|---|---|---|
| Discover files, photos, media and events? | DOCUMENTED WITH CONDITIONS | file-agent `find`/`ls`, photo-agent `search-picture`, media-agent `search`, security-monitor-agent `event-timeline`. Bounded result, setup, permissions, index completeness and parent-visible identity remain unverified. |
| Exact document evidence references? | DOCUMENTED WITH CONDITIONS | document-agent `qa` mentions evidence/coverage; `extract` and `reconcile` mention coverage/failures. Exact source path, page, excerpt, confidence and complete schemas are not guaranteed; verify actual return. |
| Transcription from arbitrary audio and timecodes? | UNKNOWN | `audio-transcription` accepts `path`, optional `language`/`speak-count`; summaries list `transcriptText`, `transcriptRef`, `segments`, source and warnings. Supported codecs, arbitrary video extraction, timecodes, offline inference and parent-visible layout are not stated. |
| Camera event → accessible recording? | DOCUMENTED WITH CONDITIONS | `event-evidence` accepts event IDs and enum `snapshot`, `clip`, `playback_position`; references are described, not guaranteed playable URLs/files, accessible from photo-agent, or complete. Event IDs from timeline are not completely specified. |
| Photo search returns a stable transferable photo ID? | UNKNOWN | `search-picture` says photo/file identity, but ID shape, stability, path conversion and `add-item` compatibility are not specified. No guarantee an existing photo can be added without copying or changing originals. |
| Music and video search → playback? | DOCUMENTED WITH CONDITIONS | media-agent search supports `play`; music `type=song` example includes `--play`, video search requires a real ID/path for playback. Selection, exact source, same result-to-play wiring, UI/device output and completion are unverified. Search is **mixed**, not inherently read-only. |
| Playback control? | DOCUMENTED WITH CONDITIONS | music `control`: pause/resume/stop, next/previous, seek, speed, volume, playback-mode and stop timer; video control: pause/continue/next/previous. `state-change`, catalog approval `none`; still require user intent and actual supported playback. No guaranteed video seek or simultaneous playback. |
| Save and retrieve a generated text file? | DOCUMENTED WITH CONDITIONS | `save-text` says workflow approval and describes `verified=true`, `outputFile`, `contentBytes`; `file-agent` can read `cat`/`find` paths. Parent transfer, destination semantics, race/conflict behavior, exact meaning of verified and read-back are untested. |
| Expert A passes an item to B? | DOCUMENTED WITH CONDITIONS | Orchestration explicitly instructs parent to pass verified business results; it does not specify complete cross-agent payloads or identifier compatibility. Only transfer values actually returned and accepted; see [edge graph](04-composition-graph.md). |
| Approve exact action and resume? | UNKNOWN | `waiting_approval` must be reported; gateway/workflow labels exist. Exact proposal UI, token, reauthorization and resume contract are not documented. Never simulate approval. |
| Verified completion? | DOCUMENTED WITH CONDITIONS | Parent reports success only after child `completed`; catalog describes action-specific summaries and some child-level `ok`/`verified`. These are not guaranteed end-to-end correctness, atomicity or proof of application-level success. |
| Repetition and idempotency? | UNKNOWN | No general idempotency keys or retry semantics documented. Duplicate album/save/download/copy is possible; do not blindly repeat a pending or failed write. |
| Detect underlying file changes? | DOCUMENTED WITH CONDITIONS | `stat`, `sha256sum` can be requested before/after. They cannot prevent a race or establish a complete immutable transaction; comparison requires exact readable paths and returned hashes. |
| Distinguish absent evidence from a negative? | DOCUMENTED AS AUTHORING BEHAVIOR | Standard says report empty/partial and never invent results; whether listings expose completeness, truncation, access errors or stable coverage is UNKNOWN. An empty query does not prove an event or file does not exist. |
| Storage health, snapshots or RAID? | UNSUPPORTED IN THIS CATALOG | `ug-photo:health` is photo CLI health, not system health. No `system-agent`, `ug-system`, snapshot, SMART, disk repair or scheduler is cataloged. Product may expose additional UI; do not equate UI with an authorized Skill API. |

Effect classification: discovery/read (47 `read` Actions); mixed read/play or read/write (4 `mixed`); mutations (27 `state-change`). Counts exclude status labels; playback may also happen inside mixed search. Semantic interpretation is documented in document QA/reconcile, photo VLM/OCR and knowledge transcription/evidence; correctness and completeness are not guaranteed. Text generation in document writing/translation is `mixed` with gateway label, and saving text is `state-change/workflow`. Explicit music/video control changes playback state despite `approval=none`. Details and exact per-operation labels are in the JSON.
