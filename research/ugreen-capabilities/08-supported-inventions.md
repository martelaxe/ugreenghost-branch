# Seven grounded combinations

These are **supported-component hypotheses**, not seven proven full device executions or claims of novelty. Parent delegates to named experts; specialist action labels are for child work, not direct parent CLI calls. Actual path/ID propagation, approval and playback remain unknown. A user-authorized selected source is assumed, never a made-up path. The proposed 60-second demonstrations are hypothetical Uliya interface interactions, not recordings of real runs. See [walkthroughs](10-end-to-end-walkthroughs.md) and [originality](09-originality-check.md).

## 1. Play a song from a handwritten set list

**User says:** “Read this photo of our set list and play the song I marked from my music library.” **NAS does:** photo-agent `vision-ocr` on the user-selected image; parent reports actual extracted line and asks for confirmation if the mark or title is unclear; media-agent `ug-music:search` (`type=song`, real keyword, `play` only after authorized correct selection). **Experience:** selected music starts if the platform returns and plays the correct real item. **Unusual:** a physical written object becomes a control for a persistent music library, with user-corrected transcription. **Why NAS:** both photo and music are already stored there. **Competitor:** [BandsManager](https://bandsmanager.com/whats-new) claims setlist-photo extraction and Spotify search; [SongDeck](https://www.songdeck.studio/) claims photo setlists and music playback. **Limits:** OCR does not guarantee marks or song identity; search result cannot be presumed stable/playable; a second query could pick a different result. Exact selected-item playback is CONDITIONAL; if not verifiable, show a match for user to play manually. **60 seconds:** select image → show actual OCR → user picks line → user requests playback → show actual media player only if real. No promise of auto-playlists.

## 2. A voice memo chooses a movie for tonight

**User says:** “In the voice memo I recorded after the festival, I mentioned a movie; find that title and play my copy.” **NAS does:** knowledge-agent `audio-transcription` for authorized memo → parent quotes returned phrase, obtains clarification on unclear name → media-agent `ug-video:search` for real title and confirmed matching item, optionally play. **Experience:** a recorded request becomes a movie being played. **Unusual:** crosses independently saved speech and a media library, but the synthesis is ordinary speech-to-title search. **Why NAS:** privately stored memo and video library in one environment; inference locality is not guaranteed. **Competitor:** [Nextcloud Assistant](https://docs.nextcloud.com/server/stable/user_manual/en/ai_assistant.html) has speech transcription and tool use; Uliya already supports media smart commands. **Limits:** unsupported codec/timestamp, no proof of identity or exact result-to-play, watch access; user must confirm. **60 seconds:** choose memo → show transcript excerpt → approve correct film → see playback if returned. No automatic jump to a passage.

## 3. The note that points to an event clip

**User says:** “My training note mentions the dog was outside around 4; show the available event evidence on my back camera then.” **NAS does:** document-agent `extract` selected note → user confirms date/time/camera and purpose → security-monitor-agent `cameras`, `event-timeline` with topic `Pet`, then `event-evidence` for an actual returned event ID. **Experience:** user receives actual event evidence references if returned and usable, alongside note excerpt. **Unusual:** a personal note supplies the context for a narrowly scoped camera review. **Why NAS:** authorized note plus local connected camera records. **Competitor:** [UGREEN Surveillance Center](https://support.ugnas.com/detail/article/en-US/866) already supports pet detection and recording search; [Frigate](https://docs.frigate.video/usage/history/) already connects events and footage. **Limits:** event ID field shape, reference playback, timezone, matching and gaps are unknown; no inference of pet identity, continuous coverage or absence. **60 seconds:** show note → time/camera confirmation → inspect actual returned event/evidence if available. Otherwise honest missing result.

## 4. A family note selects a movie and looks for subtitles

**User says:** “Find our selected family movie and check whether an English subtitle is available; let me approve it.” **NAS does:** document-agent `extract` actual title → media-agent `ug-video:search` for authorized item → `subtitle-search` with real video path → show actual `file-id` candidate and details → only after explicit user and gateway approval ask `subtitle-download`. **Experience:** a selected subtitle may be installed; play only when separately supported/requested. **Unusual:** context guides accessibility preparation, not generic search alone. **Why NAS:** local media and a family note. **Competitor:** [Plex on-demand subtitles](https://support.plex.tv/articles/subtitle-search/) already searches/downloads for playback. **Limits:** no guaranteed returned ID type, language quality, provider privacy, timing or safe collision semantics; no valid candidate → stop. **60 seconds:** note → actual candidate → explicit choice → actual completed state only if obtained. This is practical, weak novelty.

## 5. A voice memo becomes an approved keepsake file

**User says:** “Make an editable transcript of this recorded recipe and save it in my notes.” **NAS does:** knowledge-agent `audio-transcription` → parent shows actual transcript with uncertainty → after explicit save approval, knowledge-agent `save-text` with returned content and authorized destination → optionally file-agent `cat` the actual returned output path. **Experience:** an actual saved document if completed and verified. **Unusual:** spoken personal instruction becomes a reusable asset; it is mostly ordinary transcription. **Why NAS:** owned recording and notes directory. **Competitor:** [Nextcloud Assistant](https://docs.nextcloud.com/server/stable/user_manual/en/ai_assistant.html) already supports transcription. **Limits:** unsupported codecs, no guaranteed timestamps or safe overwrite; `verified` field meaning/path and read-back untested. **60 seconds:** source → preview → explicit approval → show real output only when returned, not on pending.

## 6. An event note becomes an approved photo collection

**User says:** “Using the date in this invitation, prepare a photo album from that one afternoon, but ask before creating it.” **NAS does:** document-agent `extract` date → user confirms interpretation/scope → photo-agent `search-picture` with explicit time filters → show actual bounded matches → on explicit confirmation request `create-album` with actual accepted `add-item` values or user-approved documented query. **Experience:** a real album if creation returns completed. **Unusual:** a document's time context drives a visible photo action. **Why NAS:** invitation and photos coexist; **competitor:** Uliya already offers photo management, and public [Publish-Safe Photo Review](https://devpost.com/software/publish-safe-photo-review) covers a sophisticated album workflow. **Limits:** exact photo ID/`add-item` compatibility, whether originals remain untouched, album creation/approval and selected-photo completeness unknown. **60 seconds:** note → user verifies date and candidates → approval → actual album only if returned. Similar to earlier work; low creativity.

## 7. Spoken music request with a time limit

**User says:** “My note says which track to use for tonight; play that track and stop after 15 minutes.” **NAS does:** document-agent `qa`/`extract` or knowledge-agent transcription of the specifically selected audio → parent clarifies title → media-agent music search/play → request `control` with `operation=set-stop-timer`, `stop-after-minutes=15` if playback really started. **Experience:** a real music player and requested timer, only if both expert calls actually complete. **Unusual:** archive-resident instructions drive an action with a built-in temporal endpoint. **Why NAS:** stored music and instruction. **Competitor:** ordinary music player sleep timers and [UGREEN Uliya](https://support.ugnas.com/detail/article/en-US/850) smart commands. **Limits:** stop timer effect, sequencing, timer verification, correct track and parent response unknown; no independent scheduled task implied. **60 seconds:** extract title → confirm → show track playing → actual timer result; if timer not verifiable say so. This is a useful action but not demonstrably original.
