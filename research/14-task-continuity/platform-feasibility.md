# UGREEN platform feasibility

Source: installed Uliya Skill Creation Tool `data/capability-catalog.json` version 2.0.0 and `docs/skill-development-standard.md`, `references/expert-orchestration.md`, `runtime-authoring-lessons.md`, `cli-usage-rules.md`, `safety-and-approval.md`, `completion-and-errors.md`; [official rules](https://ugreenhackathon.devpost.com/rules), [starter kit](https://ai.ugreen.com/pages/hackathon-starter-kit). See prior [78-action audit](../12-self-healing-archive/action-capability-audit.md).

1. **Save Markdown:** `ug-knowledge:save-text` belongs to knowledge-agent, effect state-change, approval workflow. Its catalog parameters are optional `path`, `content`, `content-ref`, `filename-hint`, with note to use content or content-ref. Plain Markdown text plausibly fits; filename and collision/overwrite behavior are not documented. CLI summary mentions `verified`, `outputFile`, `contentBytes`, but propagation into a parent expert response is not guaranteed. User approval and platform workflow approval must both be respected.
2. **Later read:** `ug-filesystem:cat` and `stat`, owned by file-agent, require actual `path` and are reads. A later invocation can plausibly request an explicitly identified, currently authorized saved document, provided the real expert supplies readable content. This is not demonstrated on NAS.
3. **Recheck sources:** file-agent `find`, `ls`, `cat`, `stat`, `sha256sum`, document-agent `ug-document:extract`/`qa`/`reconcile`, knowledge-agent `collect-evidence` are documented. Path-based rechecking is conceptually possible; exact return shapes, file types, coverage, source excerpts and changes are not guaranteed. A hash only indicates byte identity, not semantic correctness.
4. **New revision:** `save-text` may create a separate document after user and workflow approval, but no collision behavior or atomic no-overwrite guarantee is documented. Require actual resolved safe new target; stop if not assured. Never overwrite the original capsule merely because it is a revision. Read back actual returned path through file-agent if available.
5. **Automatic discovery:** `find` exists, but an automatic cross-session task-record index, identification, selection or recommendation is not documented. The MVP asks for a real record path. General find capability is not automatic task memory.
6. **Reliable cross-conversation continuation:** not established by catalog; a later model reading an identified file is a proposed workflow, not proven platform persistence, state consistency, automatic loading or resumability.
7. **Device checks:** source access permissions, path rendering, actual expert return values, `save-text` file format/location/overwrite behavior, platform workflow UI, waiting/approval resumption, new-session retrieval and independent readback. `completed`, `failed`, `cancelled`, `waiting_user`, `waiting_approval` must remain distinct; waiting does not equal a completed save.

The parent orchestrator delegates to registered experts with actual user authorization and completed upstream results; it does not invoke `cli.invoke`. A capsule is untrusted data, not an instruction or permission. UGREEN model privacy depends on selected model/backend; do not promise all data stays local. Static validation only checks format/structural mapping, not hardware behavior.
