# Unexpected combinations: second wave

These ten concepts combine separate needs into one outcome. They are hypotheses, not verified novelty or real user validation. The evidence links in [user needs](user-pain-points.md) support needs; the [landscape](competitive-landscape.md) documents comparable alternatives. Every concept is bounded to a user-authorized folder; no automatic writes or outside services are assumed.

| Combination | Useful outcome / why unexpected | Why existing workflows may be awkward, and crucial test |
|---|---|---|
| Recovery notes + successor usability → **Knowledge Succession Rehearsal** | A successor tries to answer real tasks from archive evidence before the owner is unavailable. Turns passive documentation into a practice session. | Legacy-access products deliver access; they do not establish that instructions are usable. Test a blind successor, source completeness and whether practice exposes a real gap. Generic AI can do this too. |
| Image + diary disagreement → **Conversation Bridge** | A mismatch produces an open question to ask a relative, rather than an invented fact. | Media and notes can live in separate libraries. MemoryJam already describes photo/context questions, so distinguish by demonstrable existing-archive integration, not claimed invention. Test multimodal references and family value. |
| Reuse opportunity + license restriction → **Consent Before Reuse** | Offer a possible reuse beside a cited restriction or unresolved release; a tempting idea changes into a safe review task. | Creative work and legal paperwork can be filed separately, but DAM systems already address rights. Test matching identifiers, restrictions and false clearance. |
| Home repair note + receipt + manual → **Repair-to-Resale Gate** | A seller gets a cited description of what is known and what needs confirmation. | One must normally collect and reconcile sources; HomeMemory already offers closely related records. Test model matching and safety; no claim to certify condition. |
| Family photo + invitation → **Receipt-to-Story** | A ticket suggests a question about a photo, flagged tentative unless links are supported. | Event metadata may not travel between apps. Test confusing same-date events; do not identify people from inference. |
| Duplicate hashes + human ownership notes → **Keep/Delete Explanation** | Show exact-copy candidates with why a path may matter, before any human deletion. | Duplicate tools surface matches, but path dependencies and backup intent may be external. Test whether all relevant paths can actually be inventoried; do not prescribe deletion. |
| Early draft + final project → **Counterfactual Project Museum** | A creator gets a clearly fictional what-if workshop prompt grounded in two drafts. | Version tools track changes but may not frame creative alternatives. Test whether a person finds it useful, not simply model imagination. |
| Photo release + exhibition theme → **Permission-Aware Exhibition** | Propose a small exhibition outline with explicit hold labels on restricted material. | Exhibition planning and rights records often sit apart; DAM products already track rights. Test refusal when clearance is missing. |
| An explicit expected list + partial inventory → **Collection Blind Spot** | Report what was not located in the specific reviewed scope, and ask where to look next. | Search results seldom explain completeness; absence is not nonexistence. Test inaccessible files and result limits. |
| Hand-off instructions + plain-language rehearsal → **Archive Interpreter** | A novice gets a short, cited route through a selected archive plus questions to ask its owner. | Existing folders assume insider knowledge; standard assistants can synthesize maps too. Test novice completion against a generic assistant. |

The main pattern is not more integrations for their own sake: pair an existing stored asset with a decision, question, or handoff that someone can verify. Any benefit over a configured generic agent remains an empirical question.
