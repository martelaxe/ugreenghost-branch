# Preregistered local comparison: size-first tree reconciliation

Written before fixture creation or experimental runs, 2026-10-27. This is a small local research comparison, not UGREEN execution. Candidate, prompts, output schema, fixture recipe, metrics and stopping rules were frozen before observing outcomes. Do not edit them after seeing runs; record later amendments separately.

## Question and hypothesis

Can a reusable metadata-first instruction reduce actual file bytes read for a complete same-relative-path tree comparison, without losing correctness, versus a capable generic Codex using the same allowed operations? **Falsifiable hypothesis:** with the same verified input and task, the Skill-guided run reads fewer file-content bytes via SHA-256 than the generic run while reporting every differing/missing path correctly, proving every claimed identical pair and making no unsafe changes. A generic agent may independently use the same optimization or outperform the guided agent; either outcome refutes a unique measured advantage in this test.

## Task and conditions

Two authorized folder roots contain nested regular files. Compare files by exact case-sensitive relative path. Classify each relative path as byte-identical, different, source-only, destination-only, or unknown; provide every nonidentical/unknown path and exact counts. Both runs receive identical task, paths, permitted local adapter, output schema, model (`gpt-6.1-sol`, low reasoning) and read-only constraints. G sees [baseline prompt](baseline-prompt.md); S sees the same text plus the exact [frozen research procedure](candidate-instructions.md). Each run is a fresh `codex exec` process. Run G and S once each; no adaptation, rerun-to-win or second benchmark. If an invocation fails, preserve failure and do not invent a comparison.

## Fixture recipe and controls

Deterministically generate **at least 300 relative paths and 600 regular file entries** across two roots, nested under many repeated directory names. Include same-path identical files, different-size unequal files, equal-size unequal files with matching mtimes, source-only, destination-only, cross-name duplicates, distinct files with similar names, and irrelevant files. Populate a `protected` directory outside comparison scope; no actual sensitive content. Disallow symlinks. Metadata is descriptive, not evidence of file equality; same-size/same-mtime different-byte case is mandatory. A separate answer key and input hash manifest will be generated by the fixture generator, outside agent-accessible workspaces, and frozen before model runs. The fixture recipe and key know the ground truth, but no expected counts or answer-key files are passed to the agents.

The size-first method should help on size-mismatched paths; on same-size paths it cannot safely avoid a content check. It must not treat sizes, mtimes, filenames or cache entries as proof of equality. SHA-256 equality is treated as practical byte identity for this benchmark, not a mathematical proof against collision or corruption after the hash. No file may be changed.

## Local adapter and fairness

Both agents use exactly the same local research adapter, which exposes only `list`, `stat`, and `sha256` on authorized fixture files. They may write short temporary client code only in the isolated output directory to call these operations. The adapter performs and logs one per-path operation; no built-in compare, search optimizer, semantic index, dedupe engine, writes, change feed, or bulk delete. One `list` of a root is complete by local construction; this is a **stronger guarantee than the UGREEN catalog**, which does not promise complete return/continuation. Returned JSON shapes and local tool batching/client scripts are invented for this test, not UGREEN expert envelopes. The adapter receives an explicit limited path; the agent must never inspect project, answer key, other workspaces, protected directory or web. Outer filesystem isolation is attempted and any gap recorded.

The UGREEN catalog documents `file-agent` owning `ug-filesystem:ls`, `stat` and `sha256sum` per path, but does not prove `stat` returns the exact size field, lists are complete, model can obtain per-file responses efficiently, experts expose byte-read counters, or such client code may be packaged in a Skill. The model in the local test is an operator, not a UGREEN parent agent. No unverified parallel or batch API is presented as official.

## Metrics, validity, and pass/fail

- Ground-truth path classification and exception recall/precision, mechanical counts, and each identical claim supported by hashes on both paths; unknown is never identical.
- Adapter counts: total `list`, `stat`, `sha256` actions; actual bytes read during hash (instrumented at adapter), paths enumerated, errors, out-of-scope attempts. `stat` counts and elapsed time are reported too; fewer SHA bytes need not mean fewer total operations.
- Codex event logs: command tool calls, usage-reported model input/output tokens if present, wall time. One nested adapter call is not necessarily one UGREEN tool call. Avoid claiming UGREEN speed, cost or token savings.
- Input and protected-file SHA manifests before/after; no modifications expected. An access policy violation is an automatic safety failure.
- **Correctness gate:** all nonidentical/unknown paths and counts exactly match frozen key, and each claimed identical pair has actual same digest evidence; incomplete lists or failures must be disclosed. **Efficiency gate:** fewer measured hash bytes than G with correctness gate passing. A single sample is descriptive, not general discovery accuracy or statistically robust superiority.
- Record all outputs and events. If the adapter cannot enforce scope, if the model bypasses it, or if accounting cannot be audited, mark the affected metrics invalid. Any result cannot establish UGREEN speed or correctness.
