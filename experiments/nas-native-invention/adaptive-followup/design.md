# Frozen follow-up design

Created before generating inputs or executing any strategy or agent, 2026-10-27. Research-only local test. No UGREEN runtime is involved.

**Question:** across contrasting file distributions, can a fixed adaptive size-first-or-hash procedure beat both static algorithms and a competent generic agent without compromising the verification frontier?

**Conditions:** deterministic reference strategies `direct`, `metadata`, `adaptive` on the same read-only fixture and same operation library, each workload repeated 3 times in rotated order; additionally one fresh generic Codex process and one fresh Codex process receiving the exact frozen procedure, same model, all five workloads and identical adapter. No adjustments or reruns to favor a condition. Mark execution errors as failures.

**Workloads:** (1) many small files, (2) fewer large files, (3) mostly equal, (4) mostly different with mixed same/unequal lengths, (5) incomplete listing plus denied per-file access, including a same-size changed pair. Deterministic generator must store ground truth separately. List completeness and access errors are injected deliberately by a local adapter and must not be presented as real UGREEN responses. Model only sees adapter results; not generator/key.

**Task:** under user-authorized two roots, classify each known relative path: `identical` only with two matching actual SHA-256 digests, `different` with two different digests or reliable unequal sizes, `source_only`/`destination_only` only if the opposite listing is complete; otherwise `unverified`. Return coverage, candidate statuses, and next safe action. No writes to input or accessing other roots. No exact budget or time SLA. Define same-size SHA as practical content evidence, not collision-proof identity or a point-in-time snapshot.

**Adaptive rule** (pre-fixed; hypothetical cost, not hardware): list roots, take up to 8 evenly spaced sorted common relative paths; request metadata and SHA on both sides for every sample, caching all outcomes. From valid samples estimate skipped bytes = (sum source+dest sizes for unequal-sized sample pairs / sample count) × remaining common pairs. Compare with `2 × remaining pairs × 262144` byte-equivalents. If estimated saved bytes is greater, choose metadata-first for the rest; otherwise choose direct hashing. The 256 KiB per metadata call is a user-chosen illustrative penalty and not a measured or UGREEN cost. If a necessary result fails, record unknown; never infer a different/missing/identity without the required evidence. Explain selection and sampling uncertainty. If sample not representative, adaptive may lose to either static method.

**Instrumentation:** actual Python-level `list`, `stat`, and SHA operations, bytes read, operation results (including digests), error records, local elapsed wall time, and path frontier. The full algorithm library is a local research artifact, not permitted Skill code. Local work runs serially without deliberate sleeping; OS page cache may affect timings. Between strategies workloads are the same and execution order rotates; no claim of cold cache or independent samples. In separate sensitivity table add a **hypothetical** 1/10/100 ms per operation to measured local algorithm time, without re-running or equating to UGREEN; real NAS calls may batch, overlap, cache or have different operation costs.

**Controls and grading:** independently compare all classifications against generated key, check each claimed evidence level against actual operation logs, require no unsafe or out-of-scope accesses, distinguish listing incompleteness from absent path; logs save returned digest. Compute local bytes and per-op count, wall time, and induced frontier. Snapshot hashes before/after. Denied accessible test file is simulated via adapter, not real OS permissions. No benchmark includes cloud or NAS. Agent actions are also audited for bypass; if unable to complete, record failure and do not infer advantage. Every reference strategy must preserve the same accuracy and safe unknowns; scoring a speedup while dropping fidelity is invalid.

**Predefined outcome interpretation:** `ADAPTIVE OPTIMIZER` only if the exact frozen guidance demonstrably beats both fixed algorithms on more than one workload and the generic agent on a practically meaningful real measured cost without accuracy/coverage loss; one run per agent is exploratory. If unclear but user-driven frontier is meaningfully observable locally, choose `VERIFICATION FRONTIER` only with explicit unverified runtime and no demonstrated user preference; otherwise `STOP THIS DIRECTION` when no added value over competent generic or existing mature software is shown. Do not claim significance or UGREEN speed from this test.
