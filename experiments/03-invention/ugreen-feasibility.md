# UGREEN feasibility — catalog audit, not runtime proof

Source: installed UGREEN creation kit 0.7.3 and `resources/uliya-skill-kit/data/capability-catalog.json` catalog 2.0.0, together with `resources/uliya-skill-kit/docs/skill-development-standard.md` and `resources/uliya-skill-kit/references/`. “Confirmed supported” below means **an appropriate action is documented in the catalog**, not that it has been executed or achieves the desired quality. The rules require official expert orchestration and prohibit custom scripts, executables, binaries and general-purpose runtimes in the submitted Skill. The parent Skill delegates only to the catalog's mapped expert; it does not directly invoke actions.

| Operation | Classification | Documented basis and limits |
| --- | --- | --- |
| File discovery | **Confirmed supported** | `ug-filesystem` → `file-agent`: `find`, `ls` are listed read actions; `find` has path, pattern, type, depth and limit fields. Scope, permissions and real returned paths need NAS validation. |

| Evidence aggregation | **Confirmed supported** | `ug-knowledge:collect-evidence` → `knowledge-agent` is cataloged with evidence, sources, coverage and failures/warnings in its return summary; confirm actual provenance granularity and scope. |
| Relationship reconstruction | **Possibly achievable through supported orchestration** | `document-agent` QA/extract/reconcile and `knowledge-agent` evidence collection may supply facts to reason over; no dedicated graph or verified relationship-reconstruction action is documented. |

| Large-archive processing | **Unconfirmed** | Catalog provides pagination/limits and document actions, but `ug-document:qa` lists max-files 1–200 default 60 and `extract` 1–500 default 60, with body caps. No validated complete processing, chunking, continuity or rate/latency guarantees. |

## Simplest credible architecture to test

An on-demand, user-authorized scope → `file-agent` inventory → `document-agent` extract/compare and `knowledge-agent` collect evidence → AI synthesis of at most a few clearly conditional hypotheses → source-referenced report, with optional approval-gated save. Explicitly surface missing coverage and expert `failed`, `cancelled`, `waiting_user`, or `waiting_approval` states. No file moves are needed for the core demonstration. Only verified results from one expert should feed the next, as required by `references/expert-orchestration.md` and `references/completion-and-errors.md`.

The weakest links are whether the supported experts can read the actual mix of files, preserve source references across multiple batches and generate reliable, constraint-aware cross-file hypotheses within the real model/context limits. No local Codex run tests any of those UGREEN behaviors. `ug-filesystem:restore` exists but its public description does not prove date-based history, version restoration or selective rollback. Graph persistence, automated background monitoring and multi-NAS control are not established by this audit.
