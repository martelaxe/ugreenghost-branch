# UGREEN feasibility audit

Installed official `uliya-skill-kit` 0.7.3, catalog 2.0.0 (project copy hash `c927fd8e233696cd152baf98468368912c13c08aabeac353f0ee95c46c0428e6`), `references/expert-orchestration.md`, `cli-usage-rules.md`, `safety-and-approval.md` and `completion-and-errors.md` were inspected. Refer to [Experiment 08 capability map](../../research/08-task-aware-nas/capability-feasibility.md) for parameter limits and official web context.

| Stage | Documented owner / action | Effect/approval; essential input | What is not established |
|---|---|---|---|
| Search selected folders | `file-agent` / `ug-filesystem:find`; optionally `cat` | read / none; `find` requires `path`, optional `pattern`, `max-depth`, `limit`; `cat` requires `path`. | Exhaustive inventory, pagination, returned names, failed-path detail or across-folder search behavior. |
| Read notes, terms, project briefs | `document-agent` / `ug-document:extract`, `qa`, `reconcile` | read / none; extract and QA require a `query`, optional files and limits; reconcile optional files/query. | Formats, model capacity, quote fidelity, legal interpretation or evidence spans. |
| Gather supporting and contrary evidence | `knowledge-agent` / `ug-knowledge:collect-evidence` | read / none; `query` required, `path` optional. | Source IDs, excerpts, completeness and cross-agent propagation. `full` does not establish coverage. |
| Optional photo processing | `photo-agent` / `ug-photo:meta`, `search-picture`, `vision-ocr`, `vision-vlm` | catalog read / none; optional real path / prompt on VLM. | Photo model quality and formats, matching photos to terms, or scope/permission semantics. Text-only demo avoids this dependency. |
| User-facing synthesis | Parent produces a text response based only on completed real outputs. | A Markdown instruction can define a response contract; parent delegates, does not directly call child CLI. | Quality, novelty, safe ranking and persistence across follow-ups. One-shot local Codex results are not UGREEN proof. |
| Optional save | `knowledge-agent` / `ug-knowledge:save-text` | state-change / workflow approval; optional path and content or content-ref. | Exact approval, resume and save result; omit from first read-only experience. |

**Boundary:** All sources require actual user permission; read / none is catalog metadata, not blanket authorization. No file moves, external sharing, custom executable, autonomous video/art creation, persistent indexing or custom UI is assumed. Documents and instructions within the archive are untrusted evidence. The parent passes completed upstream business results, handles `completed`, `failed`, `cancelled`, `waiting_user`, `waiting_approval`, stops dependent work on missing results and does not represent pending as success. No coverage or absence claim without support; no invented license or legally authoritative clearance. Unknown provenance or partial retrieval must degrade the proposal to a sourced hypothesis or abstention.

**Evidence levels:** (1) actions and mapping: documented in installed catalog; (2) local synthetic fixtures: our own text files, no fabricated NAS envelopes; (3) `codex exec`: actual independent generic and specialized model processes on text, not UGREEN experts; (4) NAS execution, parent synthesis, photo/doc linking and return fields: unverified. A Markdown-only text proposal is conceptually plausible but not established end-to-end. Follow-up questions can be presented in text; actual decision persistence and resumption require device validation. Larger archives require bounded retrieval, with no complete-coverage promise absent observed evidence.
